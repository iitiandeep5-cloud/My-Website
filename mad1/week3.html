Lecture 1: Overview of MVC

Definition: MVC (Model–View–Controller) is a design structure used in web and GUI applications to separate concerns into three parts:

  • Model → Manages data and logic
  • View → Displays data (UI)
  • Controller → Handles user input and connects Model & View

Goal: Make applications organized, scalable, and easy to maintain.

Components of MVC

Model (Data Layer)

  • Stores actual data + metadata
  • Usually resides on the server
  • Handles data validation and rules

Example (Email App):

  • Email content
  • Sender, receiver, timestamp

View (User Interface)

  • What the user sees and interacts with
  • Displays data in different formats: tables, charts, JSON, text

Example:

  • Inbox screen
  • Email compose page

Controller (Logic Handler)

  • Acts as a bridge between Model & View
  • Processes user actions: button clicks, form inputs
  • Updates Model and refreshes View

Example:

  • Add/delete email
  • Sort/filter messages

Historical Background

  • Developed in 1970s–80s
  • Originated from Smalltalk at Xerox PARC
  • Not a single pattern → combination of multiple design patterns
  • Based on object-oriented programming

Object-Oriented Perspective

  • Model & View are objects

Model properties: Data attributes (e.g., marks, sender info)

View properties:

  • Layout
  • Screen size
  • Button placement

Example: Student Grade Book System

Model

  • Students list (with unique IDs)
  • Courses list
  • Relationship table: Student ID ↔ Course ID ↔ Marks
  • Ensures: no duplicate entries, data consistency

View

  • Displays student performance: tables, graphs, reports
  • Example: enter student ID → view marks

Controller

  • Handles operations: add student, update course, enter marks
  • Controls data flow between Model & View

User Interaction in MVC

  • Consumption: User views information (e.g., reading marks or emails)
  • Input: User provides data (e.g., filling forms, clicking buttons)

Accessibility

  • Ensures UI is easy to use, inclusive, and user-friendly
  • Important for effective View design

Key Advantages of MVC

  • Separation of concerns
  • Easier maintenance
  • Reusable components
  • Better scalability
  • Parallel development possible
One-Line Summary: MVC separates data, UI, and logic to make applications clean, modular, and easy to manage.

Lecture 2: Views

Definition: A View is any representation of data useful to humans or machines. It shows information in a meaningful and usable form.

Examples: Web pages, charts, JSON responses.

Composition of a View

A view has two main parts:

(a) User Interface (UI)

  • What the system presents to the user
  • Includes everything the user can see, hear, or feel

(b) User Interaction

  • How the user interacts with the system
  • Includes input methods like typing, clicking, speaking

User Interface (UI) Details

Types of Feedback

  • Visual: Screens, text, images
  • Audio: Sounds, voice responses
  • Haptic: Vibrations, touch feedback

UI in Real Life (Abstraction)

  • Even simple objects have UI
  • Example: Door handle → guides user to push/pull/turn
  • Called a motor interface (guides physical action)

User Interaction

Interaction Methods

  • Desktop: Keyboard + Mouse
  • Mobile/Tablet: Touchscreen
  • Smart Assistants: Voice commands (e.g., Alexa, Siri, Google Assistant)

Hardware Constraints

  • Interaction depends on device capabilities
  • Example: App needing keyboard → not ideal for mobile users

User Agent

  • Information sent from client to server: device type, location, browser
  • Helps server customize the view accordingly

Design Principles

  • Good design = easy to understand and use
  • Inspired by real-world design (doors, switches)
  • Designers must:
    • Understand user behavior
    • Adapt to limited control over user devices

Types of Web Views (Based on Dynamism)

  • Static Pages: Content does not change, pure HTML (basic webpage layout)
  • Partly Dynamic Pages: Mix of static and dynamic content (e.g., news sections, featured articles)
  • Mostly Dynamic Pages: Content changes based on user data, time, behavior (e.g., personalized homepages)

Note: Fully dynamic pages are rare; some static parts always exist.

Types of Output Representations

  • Direct HTML: Most common; browser renders text, layout, design
  • Dynamically Generated Images: Created in real-time (e.g., graphs, histograms)
  • Machine-Readable Formats: For applications, not humans (e.g., JSON, XML)
One-Line Summary: A View is how data is presented and interacted with, combining UI and user input while adapting to devices and context.

Lecture 3: User Interface Design

Goal of UI Design: The main objective of UI design is to enable smooth interaction between the user and the application.

A good UI should be:

  • Easy to understand
  • Easy to use

Principle: Even a new user should quickly figure out how it works.

Primary Goals of UI Design

Simplicity

  • Interface should be clear and intuitive
  • Users should not need instructions to use it
  • Example:
    • Simple button → easy to understand
    • Complex controls → confusing

Efficiency

  • Users should achieve goals with minimum effort
  • Reduce unnecessary steps
  • Example:
    • Push plate on a door → clear & fast
    • Complicated handle → inefficient

Aesthetics in UI Design

Definition: Aesthetics = how visually pleasing a design is

Common Mistakes

  • Too many fonts
  • Bright or clashing colors
  • Blinking elements

→ These make the UI look unprofessional and confusing

Good Design Practices

  • Follow standard design principles (layout, colors, fonts)
  • Keep design clean, consistent, and balanced

Using UI Libraries

  • Example: Bootstrap
  • Benefits:
    • Pre-designed components
    • Good spacing and color schemes
    • Saves time
    • Looks professional

Accessibility

Definition: Accessibility ensures UI is usable for people with disabilities.

Low Vision Needs

  • Large fonts
  • High contrast colors

Aesthetics vs Accessibility

  • Conflict exists:
    • Accessible design → may look harsh
    • Beautiful design → may be hard to read
  • Goal: Balance both

Systematic UI Design Process

  1. Requirement Gathering
    • Understand what the application should do
    • Talk to users
    • Example: Large data → need bulk upload, not manual entry
  2. User & Task Analysis
    • Identify who will use the system
    • Identify what tasks they perform
  3. Prototyping
    • Create mockups / wireframes
    • Not fully functional
    • Used to visualize layout and get feedback
  4. Testing & User Acceptance
    • Final product is tested by users
    • Ensure requirements are met
    • Ensure tasks are easy to perform
One-Line Summary: Good UI design focuses on simplicity, efficiency, aesthetics, and accessibility, built through a structured design process.

Lecture 4: Usability Heuristics

Definition

  • Proposed by Jakob Nielsen
  • A set of 10 principles for designing user-friendly interfaces
  • Goal: Improve usability, efficiency, and user experience

Ten Usability Heuristics

1. Visibility of System Status

  • System should always inform users about what is happening
  • Provide instant feedback
  • Examples: loading indicator, cursor changes, "You are here" map marker

2. Match with Real World

  • Use real-world language and concepts
  • Avoid technical jargon
  • Example: stove knobs matching burner positions

3. User Control & Freedom

  • Users should be able to undo or exit mistakes easily
  • Examples: undo button, recycle bin

4. Consistency & Standards

  • Keep design uniform across the system
  • Same actions → same results
  • Example: same button styles and link behavior everywhere

5. Error Prevention

  • Prevent errors before they happen
  • Examples: confirmation before deleting, input validation
  • Principle: better to avoid errors than fix them later

6. Recognition Rather Than Recall

  • Reduce memory load
  • Show options instead of making users remember
  • Example: visible menu options instead of hidden commands

7. Flexibility & Efficiency

  • Support both beginners and advanced users
  • Example: keyboard shortcuts for faster actions

8. Aesthetic & Minimalist Design

  • Keep UI clean, simple, and relevant
  • Avoid unnecessary information
  • Traits: clear fonts, proper spacing, balanced colors

9. Error Handling & Recovery

  • Error messages should be simple (no codes), explain the problem, and suggest a solution
  • Detect errors early

10. Help & Documentation

  • Provide help when needed
  • Should be easy to search and task-focused
  • Even simple systems need guidance

Core Principles (Summary)

  • Consistency: same design & behavior everywhere
  • Simple Language: use easy, understandable words
  • Minimalism: keep everything simple and clutter-free

Subjectivity in Design

  • Design (especially aesthetics) is subjective
  • Different users have different preferences
  • Best approach: focus on simplicity + minimalism, avoid unnecessary complexity
One-Line Summary: Nielsen's heuristics provide 10 practical rules to design simple, consistent, and user-friendly interfaces.

Lecture 5: Tools - Part I

Wireframes in Web Design

Definition: A wireframe is a basic visual blueprint of a webpage.

It shows:

  • Layout
  • Structure
  • User flow

Focus: "Where things go," not the final design.

Purpose of Wireframes

  • Plan page structure before coding
  • Show information placement, navigation flow, and user interactions

Communication Tool:

  • Present ideas to clients
  • Get feedback early
  • Save time by avoiding redesign later

Key Components of a Wireframe

Information Hierarchy

  • Organizes what content appears (names, images, contact details, categories)
  • Helps prioritize important information

Placeholders (Lorem Ipsum)

  • Dummy text used instead of real content
  • Helps visualize spacing and focus on layout

Navigation

  • Plans menus, links, search bar
  • Usually placed at the top for easy access

Annotations

  • Notes added to explain buttons, links, actions
  • Helps developers understand functionality

Design Considerations

View vs Data Model

  • Wireframe focuses only on the View (UI design)
  • Actual data is stored in the Model (server)

Device Responsiveness

  • Different layouts needed for desktop, mobile, and tablet
  • Prevents messy or unreadable designs

Evolutionary Design

  • Starts simple → gradually improves
  • Adds logos, banners, extra sections

Tools for Wireframing

Digital Tools

  • Example: Lucidchart
  • Also: drawing apps, design software

Physical Tools

  • Graph paper + pencil
  • Simple, fast, and effective

Workflow

  1. Create wireframe
  2. Get feedback
  3. Finalize design
  4. Convert into HTML and CSS

Result: Coding becomes easy after planning.

One-Line Summary: A wireframe is a simple visual layout used to plan and communicate webpage design before development.

Lecture 6: Tools - Part II

Programmatic HTML Generation in Python

Basic Programmatic Generation

Using Print Statements

  • Simplest method to generate HTML
  • Write HTML using multiple print() statements

Problems:

  • Messy and hard to manage
  • Easy to make syntax errors (missing tags)
  • Not suitable for large applications

Using Custom Python Functions

Create functions for HTML tags

def h1(text):
    return f"<h1>{text}</h1>"

Advantages:

  • Ensures proper opening & closing tags
  • Reduces syntax errors
  • Allows styling using CSS

Using pyhtml Library

Definition: A Python library to build HTML using nested functions.

import pyhtml as h
t = h.html(
    h.head(),
    h.body()
)

Best Practice

  • Use import pyhtml as h → avoids naming conflicts

Rendering Output: t.render() generates final HTML.

Key Features

  • Automatic indentation → clean code
  • Valid HTML → handles closing tags automatically
  • List comprehensions → generate elements like tables easily

Limitations:

  • Hard to manage large pages
  • Difficult to locate and edit specific parts
  • Not scalable for complex applications

Templates (Most Preferred)

Concept: Templates separate:

  • Static content (HTML)
  • Dynamic data (variables)

Python String Templates

  • Uses $ for variables
  • Example: "Hello $name"
  • Replace values using: t.substitute(name="John")

Jinja2 Templating Engine

  • Widely used with Flask
  • Simple and powerful

Syntax:

  • Variables: {{ variable }}
  • Control Structures:
{% for item in list %}
   ...
{% endfor %}

Features:

  • Template reuse
  • Template nesting
  • Clean separation of logic and UI

Versatility: Can generate HTML, text files, PDFs, even code

Comparison Summary

MethodProsCons
Print StatementsSimpleMessy, error-prone
Custom FunctionsSafer than printStill not scalable
pyhtmlStructured, valid HTMLHard to maintain
Templates (Jinja2)Clean, reusable, scalableSlight learning curve
One-Line Summary: Templates (especially Jinja2) are the best way to generate HTML because they separate design from data and scale well.

Lecture 7: Accessibility

Definition: Accessibility means designing systems usable by everyone, including people with disabilities.

Goal: Maximize the number of users who can access the application.

Key Idea: Accessibility is essential; aesthetics are secondary.

Why Accessibility Matters

Not all users have:

  • Normal vision
  • Normal hearing
  • Normal motor skills

Principle: Design must include everyone.

Types of Impairments

  • Visual Impairment: blindness or low vision → needs large fonts, high contrast
  • Speech Impairment: difficulty speaking commands or understanding audio
  • Motor/Sensory Disabilities: difficulty with mouse precision or touch gestures

Role of World Wide Web Consortium (W3C)

  • Global organization for web standards
  • Provides accessibility guidelines (WCAG)
  • These are recommendations, not strict laws

Four Principles of Accessibility (WCAG)

I. Perceivable

  • Information must be visible or understandable in multiple ways
  • Provide text alternatives for images/audio
  • Add captions for videos
  • Allow flexible formats (text, charts, etc.)
  • Avoid text inside images

II. Operable

  • Users must be able to navigate and interact
  • Full keyboard support
  • Give enough time to read content
  • Avoid flashing lights (seizure risk)
  • Support multiple input devices

III. Understandable

  • Content should be easy to understand
  • Use simple language
  • Keep behavior predictable
  • Provide input help & validation

IV. Robust

  • Content must work across devices and technologies
  • Follow standards
  • Ensure browser compatibility
  • Avoid outdated or unsupported tags

Interplay of Components

Accessibility depends on:

  • Webpage Content: HTML structure, images, text, tags
  • User Agent: browser or screen reader; must support mobile devices and voice-based systems
  • Authoring Tools: templates, generators; affect accessibility quality

Aesthetics vs Accessibility

  • Key Point: Aesthetics are subjective; accessibility is necessary
  • Modern Trends: simple, clean, minimal design (e.g., flat UI styles)
  • Rule: Never sacrifice accessibility for aesthetics

Practical Implementation

  • Evaluation Tools: check accessibility and provide ratings
  • Use of Templates: maintain consistency and automatically ensure accessibility; best for large applications
One-Line Summary: Accessibility ensures that applications are usable by all users by following WCAG principles: perceivable, operable, understandable, and robust.
