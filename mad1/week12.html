Lecture 1: Components of an App

Introduction to Deployment

Definition

  • Deployment: Process of making your application available to users.
  • Transition: Local (your laptop) → Remote server (internet).

Local Development vs Deployment

Local Development

  • Code runs on your personal computer.
  • Uses: Source code, images, CSS, documents.

Limitations of Local Systems

  • Availability: Laptop not always on.
  • Reliability: Crash = downtime/data loss.
  • Capacity: Cannot handle many users/services.

Requirements for Deployment

  • Dedicated servers to run the app.
  • Always-on internet with high bandwidth.
  • Power backup and cooling (data center infrastructure).

Data Centers & Cloud

  • Data Centers: Facilities with servers, cooling, and high-speed internet.

Cloud Computing

  • Shared infrastructure (no need to own servers).
  • Major Providers: Amazon Web Services (AWS), Google Cloud, Microsoft Azure.

Benefits

  • No hardware management.
  • Scalable.
  • Cost-effective.

App Scaling & Infrastructure

  • Scaling: Handling growth (few users → millions of users).

Networking Basics

  • HTTP: Communication between browser and server.
  • DNS: Converts domain (e.g., google.com) → IP address.

Optimization Strategies

  • Splitting Services: Frontend and database on separate machines → optimized performance.
  • Security (HTTPS): Encryption using secure servers.
  • Load Balancer: Distributes traffic across servers → improves speed and reliability.
  • Logging: Records system activity → helps debugging, monitoring, and security.
  • Content Delivery Network (CDN):
    • Purpose: Deliver static files quickly.
    • Examples: Libraries (React, Bootstrap), images.
    • Advantages: Faster loading, reduced server load, cached in browser.

Deployment Complexity

  • Building an app = easy.
  • Deploying at scale = hard.

Required Infrastructure

  • Always-on servers.
  • Auto-restart systems.
  • Monitoring and logging.
  • High-speed networks.

Containers (Advanced)

  • Help package applications for deployment.
  • Concept: Lightweight environments for portability and consistency.

Quick Summary

  • Deployment = local → live app.
  • Local systems are unreliable for real users.
  • Use cloud and data centers.
  • Scaling requires load balancers, service separation, logging.
  • CDN speeds up static content delivery.
  • Deployment is complex but essential.

Lecture 2: Service Approach I

Idea: Specialization

  • Work is divided among experts.
  • Traditional Approach:
    • One person manages everything (hardware, power, networking, OS).
    • Complex and inefficient.
  • Service Approach:
    • Datacenter providers handle infrastructure.
    • Developers focus on coding.
    • More efficient and scalable.

Key Service Categories

Software as a Service (SaaS)

  • Ready-to-use software via internet.
  • No installation required.
  • Examples: Google Docs, Gmail, Microsoft Office 365, WordPress, GitLab.
  • Features: Fully managed, no maintenance needed.

Infrastructure as a Service (IaaS)

  • Provides virtual machines/servers.
  • Responsibility Split:
    • Provider → hardware, power, network.
    • User → OS, updates, security.
  • Examples: Amazon Web Services, Google Compute Engine, Microsoft Azure, DigitalOcean, Linode.

Platform as a Service (PaaS)

  • Provides platform + tools + infrastructure.
  • Features:
    • Pre-configured environment (Python, PHP, etc.).
    • Just deploy code → it runs.
  • Includes: Database support (MySQL, Redis, Firebase), built-in scaling support.

Physical Infrastructure (Datacenters)

  • Secure buildings.
  • Fire protection systems.
  • Cooling systems.
  • High-speed internet.
  • Backup power.
  • Permanent IP addresses.

Case Studies

Replit

  • Focus: Learning & development.
  • Uses Poetry (dependency manager).
  • Provides Linux shell access, shared CPU/RAM.
  • Limitation: Shuts down after inactivity, resets server state.

Glitch

  • Similar to Replit.
  • Better for simple app deployment.
  • Supports collaborative coding.
  • Classification: Both are PaaS.
    • Manage server + networking + tools.
    • Provide browser-based editors.

Quick Summary

  • Service approach = specialization of tasks.
  • Three models:
    • SaaS: Ready-to-use apps.
    • IaaS: Raw infrastructure.
    • PaaS: Ready platform for developers.
  • Datacenters provide secure, always-on systems.

Lecture 3: Service Approach II

Overview of Google App Engine (GAE)

Introduction

  • Google App Engine (GAE): A Platform as a Service (PaaS).
  • Unlike Google Compute Engine (IaaS), there is no need to manage virtual machines.
  • Key Idea: GAE handles web server, runtime (Python, etc.), and scaling → developers focus only on code.

Google Cloud Console

  • Access via dashboard.
  • Provides:
    • Requests per second.
    • Application status.
    • Monitoring and logging.
    • HTTPS setup.

Pricing

  • Paid service.
  • Free tier and trial credits available.

Development Tools in GAE

Google Cloud Shell

  • Linux environment.
  • Provides: 4 CPUs, 16 GB RAM.
  • Pre-installed cloud tools.

Cloud Editor

  • Browser-based code editor.
  • Similar to VS Code.
  • Interface style: professional development and scaling focus.

Comparison of Platforms

  • Replit: Best for learning and collaboration; auto shuts down when idle.
  • Glitch: Good for small deployment and testing; supports collaborative development.
  • Google App Engine: More complex; best for large-scale apps and production systems.

Key Characteristics of PaaS

Provider manages:

  • Operating system.
  • Web server.
  • HTTPS security.
  • Storage.
  • Crash recovery.

Other PaaS Providers

  • AWS Elastic Beanstalk.
  • Heroku.

Supported Tech Stacks

  • Python: Flask, Django.
  • PHP: Laravel.
  • JavaScript: Node.js, React.

Integration & Best Practices

  • Version Control: Track changes in code.
  • CI/CD: Continuous Integration, Continuous Delivery, Continuous Deployment → automates testing and deployment.
  • Scaling & Automation: Automatically handle user growth, reduce manual work.

Quick Summary

  • GAE = PaaS → no server management needed.
  • Console → monitor app performance.
  • Tools: Cloud Shell + Cloud Editor.
  • Replit/Glitch = beginner tools.
  • GAE = production-level scaling.
  • PaaS handles OS, security, deployment.
  • Best practices: version control, CI/CD, scaling.

Lecture 4: Deployment

Version Control

  • Definition: System to track code changes over time.

Why Use It?

  • Track history.
  • Avoid breaking working code.
  • Experiment safely.

Git Branching Workflow

Main Branches

  • Master/Main: Final, stable version (production code).
  • Develop: Daily development happens here.

Supporting Branches

  • Feature Branch: For new features, merged into develop.
  • Hotfix Branch: Fix urgent bugs, created from master, merged into master + develop.
  • Release Branch: Prepare final version, bug fixing before release.

Key Git Operations

  • Merge: Combine branches.
  • Push: Upload code to server.
  • Pull Request (PR): Code review before merging.

Distributed vs Centralized Systems

  • Git (Distributed):
    • Work offline.
    • No file locking.
  • Old Systems (Centralized):
    • Example: SVN.
    • Required locking.

Popular Platforms

  • GitHub.
  • GitLab.
  • Bitbucket.

Continuous Integration (CI)

  • Definition: Automatically integrates and tests code changes.
  • How It Works: Developer pushes code → server builds project and runs tests.

Best Practices

  • Test-Driven Development (TDD): Write tests before code.
  • Code Review: Peer feedback before merge.
  • Fast Pipelines: Keep testing quick.

Continuous Delivery & Deployment (CD)

Continuous Delivery

  • Code is packaged and ready for release.
  • Example: downloadable build.

Continuous Deployment

  • Code is automatically deployed to production.
  • Live immediately.

Pros & Cons

  • Benefits: Faster bug fixes, quick feature releases, seamless updates.
  • Risks: Bugs may reach users, system crashes possible if tests fail.

Quick Summary

  • Git: Track changes and manage code safely.
  • Branches: Main, Develop, Feature, Hotfix, Release.
  • CI: Auto test and integrate code.
  • CD: Auto deliver and deploy code.
  • Platforms: GitHub, GitLab, Bitbucket.
  • DevOps: Automation and faster delivery.

Lecture 5: Containers

Definition

  • Container: A self-contained environment with:
    • Minimal operating system.
    • Required libraries.
    • Application.
  • Runs a specific process independently.

Containers vs Virtual Machines (VMs)

Feature Containers (Efficient) Virtual Machines (Heavy)
Size Lightweight Heavy
Speed Fast startup Slower
Operating System Shared OS kernel Full OS
Resource Usage Low High
Conclusion: Containers are more efficient than VMs.

Core Mechanisms

  • Linux Kernel: Core system software managing hardware and resources.
  • Namespaces: Isolate processes; each container has its own environment.
  • Control Groups (cgroups): Limit resource usage (CPU, memory).
  • Process Isolation: One process cannot affect another.
  • Sandboxing: Each container runs in its own restricted environment; failure in one does not affect others.
  • Networking: Containers communicate via defined networks, not direct data sharing.

Benefits of Containers

  • Lightweight and fast.
  • Easy version control.
  • Portable (runs anywhere).
  • Simplifies deployment.
  • Works well with CI/CD pipelines.

History & Evolution

  • 1970s: chroot → basic isolation.
  • 2000s: FreeBSD Jail → improved isolation.
  • Linux projects: openVZ, VServer.
  • 2008: Namespaces added → modern containers.

Key Tools

  • Docker: Most popular container tool; manages containers and images.
  • Docker Compose: Simple multi-container setup.
  • Kubernetes: Advanced orchestration; used for large-scale systems.

Containers in Scaling

  • Replace heavy servers with multiple containers.
  • Used for:
    • Load balancing.
    • Web servers.
    • Databases.
    • Logging systems.

Middleware Concept: Components between frontend and backend:

  • Authentication.
  • Load balancing.
  • Proxy.
  • Logging.

Development Workflow

  1. Requirements.
  2. Development & Testing.
  3. Integration.
  4. Packaging (containers).
  5. Deployment (PaaS/cloud).

Quick Summary

  • Container = lightweight isolated environment.
  • Uses Linux kernel (namespaces + cgroups).
  • Faster and more efficient than VMs.
  • Tools: Docker, Kubernetes.
  • Helps in scaling, CI/CD, and deployment.
