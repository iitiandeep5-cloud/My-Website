Lecture 1: Information Representation in a Machine

Markup & User Interface (UI)

  • Definition: Markup controls how content appears on a screen (layout, structure, design).
  • Role in UI: A key part of the User Interface (UI), focusing on aesthetics and usability.
  • Purpose: Developers use markup to change appearance without altering content.
  • Technologies:
    • HTML5 → Defines structure (what is on the page).
    • CSS → Defines styling (how it looks).
Analogy: HTML = skeleton, CSS = styling/beauty.

Information Representation (Bits)

  • Binary System: Computers use bits (0 and 1).
  • Electrical Meaning:
    • 0 → low voltage (0V).
    • 1 → high voltage.
  • Advantages:
    • Enables mathematical computations.
    • Reliable (noise-resistant).
Key Idea: Everything in a computer (text, images, videos) is a sequence of bits.

Context & Interpretation of Bits

  • Meaning: Bits alone have no meaning; context defines interpretation.
  • Examples:
    • 0110 → 6 (number system).
    • 1010 → +10 (unsigned), –6 (2's complement).
    • 01000001 → Number 65, Character 'A', or just a binary sequence.
  • In Memory: Programs define context (variable, string, number).
Key Idea: Bits + Context = Meaning.

Text Encoding Standards

To share data, computers need a common encoding system.

ASCII

  • Developed in 1960s–70s.
  • 7-bit system → 128 characters.
  • Includes:
    • Letters: A–Z, a–z.
    • Digits: 0–9.
    • Symbols: @, $, %.
    • Control characters: Enter, Backspace.
  • Extended ASCII: 8-bit (256 characters), supports European special characters.

Unicode

  • Created to support all world languages.
  • Handles languages like Hindi, Tamil, Chinese, Japanese.
  • Types:
    • UCS-2 → 2 bytes (65,536 characters).
    • UCS-4 → 4 bytes (~4 billion characters).
  • Current Status:
    • 100,000+ characters defined.
    • Plenty of space for future expansion.

Quick Summary

Markup (HTML + CSS) → Controls UI appearance.
Bits (0/1) → Basic unit of all data.
Context → Gives meaning to bits.
Encoding (ASCII, Unicode) → Standard way to represent text.

Lecture 2: Efficiency of Encoding

Encoding Efficiency Problem

  • Background: ASCII worked well due to English dominance in early web content.
  • Problem with UTF-32 (UCS-4):
    • Uses 4 bytes per character.
    • Example (5,000 characters):
      • UTF-32 = 160,000 bits.
      • ASCII (8-bit) = 40,000 bits.
      • ASCII (7-bit) = 35,000 bits.
  • Impact:
    • More storage required.
    • Higher memory usage.
    • Slower processing.
Key Idea: Universal encoding ≠ efficient encoding.

Frequency-Based Encoding & Compression

  • Character Frequency:
    • Frequent letters: E, T.
    • Rare letters: Z, Q, J.
  • Huffman Encoding:
    • Short codes → frequent characters.
    • Long codes → rare characters.
    • Example: 5,000 characters → 10,000–20,000 bits.
  • Data Compression:
    • Tools like ZIP compress data using patterns and frequencies.
    • Works for text, images, videos, etc.
Key Idea: Smarter encoding = less space.

Variable-Length Encoding (Unicode Solution)

  • Goal: Balance efficiency with global language support.
  • Encodings:
    • UTF-8:
      • Uses 1 to 4 bytes.
      • ASCII-compatible.
      • Rule: If byte starts with 0 → ASCII character.
      • Most widely used on the web.
    • UTF-16:
      • Uses 2 or 4 bytes.
      • More efficient for some languages.
    • UTF-32:
      • Always 4 bytes.
      • Simple but least efficient.
Key Idea: Common characters → fewer bytes; rare characters → more bytes.

UTF-8 Working (Prefix Codes)

  • Prefix Rules:
    • Starts with 0 → 1-byte (ASCII).
    • Starts with 11 → start of multi-byte character.
    • Starts with 10 → continuation byte.
  • Feature: Self-Synchronization
    • Detects start and middle of a character.
    • Makes text easy to process and recover.
  • Capacity: Supports ~1 million characters (enough for all languages).

Practical Encoding Examples

CharacterCode PointUTF-8 Size
'A'U+00411 byte
HebrewU+05D02 bytes
KanjiU+597D3 bytes
RareU+233B44 bytes

Pattern: More complex/rare characters → more bytes.

Importance in Web Development

  • Global Support: Apps must support languages like Hindi, Tamil, Chinese.
  • Browser Handling: Browsers rely on UTF-8 to display text correctly and process strings.
  • HTML Standard Practice: <meta charset="UTF-8">
    • Ensures correct display across devices.
    • Prevents encoding errors.

Quick Summary

UTF-32 → Simple but inefficient.
Huffman Encoding → Compress using frequency.
UTF-8 → Best balance (efficient + universal).
Prefix Codes → Identify character length.
UTF-8 → Standard for web development.

Lecture 3: What is Markup?

Definition & Purpose of Markup

  • Definition: Markup = adding codes/cues in text to control how it is displayed.
  • Separation:
    • Content → what is written.
    • Presentation/Meaning → how it appears or is interpreted.
  • Purpose: Makes text clear, structured, and easy to understand.
  • Usefulness:
    • For humans → readability.
    • For machines → processing.
  • Everyday Examples: Punctuation (., ?, !), capitalization.
Key Idea: Markup gives structure + meaning to raw text.

Historical & Conceptual Background

  • Origin: From editing on paper (marking titles, headings, corrections).
  • Computing Use: Since 1970s (e.g., LaTeX).
  • Importance: Helps machines identify parts like abstract, introduction, results.
  • Benefit: Machines don't need to "understand" text like humans.
Key Idea: Markup enables automation and structured processing.

Types of Markup

1. Presentational Markup

  • Focus: Appearance (look).
  • Basis: WYSIWYG (What You See Is What You Get).
  • Features: Immediate visual output.
  • Example: Bold text, center alignment.
  • Drawback: Code is complex and hard to read in raw form.

2. Procedural Markup

  • Focus: Step-by-step instructions.
  • Example:
    • Set font → Arial.
    • Set size → 24pt.
    • Add spacing.
  • Advantage: Simple for machine to follow.
Key Idea: Tool doesn't need to be smart → just follow instructions.

3. Descriptive (Semantic) Markup

  • Focus: Meaning, not appearance.
  • Example:
    • <title> instead of "make bold".
    • <heading> instead of "increase font size".
  • Advantages:
    • Tool-independent.
    • Long-term usability.
    • Better for search and data processing.
Key Idea: Most important type in modern systems.

Semantics vs Presentation

  • Semantics: Meaning + structure of content. Answers: "What is this?"
  • Presentation: Visual appearance. Answers: "How does it look?"
  • Semantic Languages: HTML, XML, LaTeX.
  • Example:
    • Presentational: "Make text bold."
    • Semantic: "This text is important (emphasis)."
  • Outcome: Display system decides bold/color/style.

Problem with WYSIWYG Tools

  • Example: Microsoft Word.
  • Produces: Complex, bloated code.
  • Issue: When converted to HTML → messy, hard to read, hard to maintain.
Key Idea: WYSIWYG = easy for users, messy for developers.

Quick Summary

Markup = structure + display instructions.
Types: Presentational → looks. Procedural → steps. Descriptive → meaning.
Semantic markup → most powerful.
WYSIWYG tools → easy but inefficient.

Lecture 4: Introduction To HTML

History & Origin of HTML

  • Creation: HTML (HyperText Markup Language) was created by Tim Berners-Lee in 1989 at CERN.
  • Inspiration: Based on SGML (Standard Generalized Markup Language).
  • Key Difference:
    • SGML → strict rules.
    • HTML → forgiving, error-tolerant.
  • Browser Behavior: Browsers follow "best effort interpretation." Even with missing/wrong tags, pages still display.

Core Structure & Syntax

  • Basic Structure: Starts with <!DOCTYPE html>.
  • Tags:
    • Written using angle brackets < >.
    • Usually in pairs: <tag> … </tag>.
  • Case Rule: Case-insensitive (<h1> = <H1>), but lowercase is best practice.
  • Common Elements:
    • <html> → root element.
    • <body> → main content.
    • <h1> → heading.
    • <p> → paragraph.
  • Nesting Rule: Tags can be inside others.
    • Correct: <p><b>Text</b></p>.
    • Wrong: <p><b>Text</p></b>.
  • Rule: Close inner tag first, then outer tag.

Semantic vs Physical Markup

Semantic (Logical) Markup

  • Focus: Meaning of content.
  • Examples:
    • <strong> → important text.
    • <em> → emphasized text.
  • HTML5 Semantic Tags:
    • <nav> → navigation.
    • <footer> → footer section.
    • <div> → block container.
  • Benefits: Better for SEO, accessibility (screen readers), and code clarity.

Physical (Presentational) Markup

  • Focus: Appearance only.
  • Examples:
    • <b> → bold.
    • <center>, <font> → deprecated.
  • Problem: No meaning, only styling.
Key Idea: Use semantic markup > physical markup.

Evolution of HTML

  • Versions Timeline:
    • HTML (1990) → first version.
    • HTML 2 (1995).
    • HTML 3/4 (1997).
  • XHTML:
    • Based on XML.
    • Stricter rules, cleaner structure.
  • HTML5 (Modern Standard):
    • Developed in 2008, standardized in 2014 (W3C).
    • Key Features: Replaced Adobe Flash; added <audio> and <video> support.
    • Now the most widely used version.

DOM (Document Object Model) & APIs

  • DOM Concept: Browser converts HTML into a tree structure.
<html>
  <body>
    <p>
  • Importance: Enables dynamic updates and interactive web pages.
  • DOM Manipulation: Developers use JavaScript to:
    • Change content.
    • Modify styles.
    • Add/remove elements.
  • HTML5 APIs:
    • Canvas → drawing graphics.
    • Offline API → run apps without internet.
    • Web Storage → store data locally.
    • Drag & Drop → interactive UI features.
  • Related Technologies:
    • JavaScript → controls behavior (DOM manipulation).
    • CSS → controls design & layout.

Quick Summary

HTML created by Tim Berners-Lee (1989).
Forgiving language → works even with errors.
Tags + nesting → define structure.
Semantic > physical markup.
HTML5 → modern standard (audio, video, APIs).
DOM → tree structure of webpage.
JavaScript + CSS → behavior + styling.

Lecture 5: Introduction To Styling

Markup vs Styling (Core Concept)

  • Markup: Defines structure and meaning of content.
    • Example: <h1> → heading.
    • Does not control appearance.
  • Styling: Controls appearance (look & design).
    • Includes colors, fonts, layout.
  • Separation of Concerns: Keep markup (HTML) and styling (CSS) separate.
    • Benefits: Same content → different designs; easy maintenance; flexible UI design.
Key Idea: HTML = structure, CSS = appearance.

Themes

  • Definition: Theme = different visual styles for the same content.
  • Examples: Light mode, Dark mode.
  • Important: Functionality remains the same; only appearance changes.
Key Idea: Themes = styling applied on same structure.

Style Sheets & CSS

  • Style Sheets: Files containing only styling rules. Define how HTML elements should look.
  • CSS (Cascading Style Sheets): Purpose is to separate design from content.
  • Cascading Concept: Multiple styles can apply to the same element.
    • If conflict occurs → last rule wins.
  • Example: Two styles for <p> → latest one is applied.

Browser Developer Tools

  • Definition: Built-in tools in browsers (Chrome, Edge, etc.).
  • Uses: View HTML structure, inspect CSS styles, debug UI issues.
  • Benefits:
    • Identify which code affects which element.
    • See applied styles in real-time.
Key Idea: Bridge between code and visual output.

Default Browser Styles

  • Behavior: If no CSS is written, browser applies default styling.
  • Examples:
    • Headings (<h1>): display: block; font-size: ~2em; font-weight: bold; margin above & below.
    • Links (<a>): color: blue; text-decoration: underline; cursor changes to pointer on hover.
Key Idea: Browsers ensure basic readability by default.

Important CSS Properties

  • Text Styling:
    • font-size → text size.
    • font-weight → thickness (bold).
  • Colors:
    • color → text color.
    • background → background color.
  • Layout:
    • display → positioning (block, inline, etc.).
  • Effects:
    • text-decoration → underline, etc.
    • cursor → mouse pointer style.

Quick Summary

Markup → structure (HTML).
Styling → appearance (CSS).
Separation → flexibility & reusability.
CSS → cascading (last rule wins).
Browser → default styles applied.
Dev tools → debug & inspect UI.

Lecture 6: Types of CSS Styling and Responsive Websites

Types of CSS Styling: CSS allows developers to override browser default styles by adding new rules.

Inline CSS

  • Definition: Applied directly inside an HTML tag.
<h1 style="color: blue;">Heading</h1>
  • Advantage: Quick and specific changes.
  • Disadvantage: Not reusable, hard to maintain (must change every tag manually).

Internal CSS

  • Definition: Written inside <style> tag (in <head> section).
<style>
h1 {
  color: blue;
}
</style>
  • Advantage: Styles apply to entire page, easier to manage than inline.

External CSS

  • Definition: Stored in a separate .css file, linked to HTML.
<link rel="stylesheet" href="style.css">
  • Advantages:
    • Reusable across multiple pages.
    • Cleaner code.
    • Faster loading (browser caching).
Key Idea: External CSS = best practice.

Cascading Concept

  • Definition: CSS works in layers (cascade).
  • Rule: If a style is missing, browser checks lower layers.
  • Priority Order:
    1. Inline CSS.
    2. Internal CSS.
    3. External CSS.
    4. Browser default.
Key Idea: Closest (top) rule wins.

Responsive Web Design

  • Goal: Make websites work on desktop, tablet, and mobile.
  • How it Works: HTML stays the same, CSS changes based on screen size.
  • Adaptive Changes:
    • Horizontal layout → vertical layout.
    • Font sizes adjust.
    • Menus → hamburger menu.
    • Better use of screen space.
Key Idea: One website → works on all devices.

CSS Frameworks (Bootstrap)

  • Definition: Frameworks are pre-built CSS components that save development time.
  • Bootstrap:
    • Open-source, developed by Twitter.
    • Features: Mobile-first design; ready-made components: buttons, forms, navigation.
Key Idea: Faster UI development with ready styles.

Role of JavaScript

  • Definition: A programming language for adding behavior to web pages.
  • Difference:
    • HTML → structure.
    • CSS → styling.
    • JavaScript → behavior.
  • Uses:
    • Form validation (e.g., email check).
    • Dynamic content generation.
    • DOM manipulation.
Key Idea: JavaScript makes websites interactive.

Core Principle of Web Development

  • Separation of Concerns:
    • HTML → Content.
    • CSS → Style.
    • JavaScript → Behavior.
  • Benefits:
    • Easy to maintain.
    • Flexible design.
    • Works across devices.

Quick Summary

CSS types → Inline, Internal, External.
Cascading → top rule overrides lower.
Responsive design → adapts to screen size.
Bootstrap → ready-made UI framework.
JavaScript → adds interactivity.
Core idea → separate content, style, behavior.
