Lecture 1: Beyond HTML

Focus

  • What comes after HTML & CSS → building dynamic, interactive applications.
  • Approach: Learn core concepts, not specific frameworks.
  • Benefit: Easier adaptation to new technologies.

Fundamentals of Markup Languages

  • Markup: Adding tags to text to give meaning and structure.
  • Origin: 1960s (typesetting & publishing).
  • Purpose:
    • Machine-readable.
    • Extract structured info (e.g., table of contents).
  • Evolution: Different users → different markup styles.
  • Works across print, web, and digital media.

SGML (Standard Generalized Markup Language)

  • Meta-language: Used to create other markup languages.

Key Concepts

  • DTD (Document Type Definition): Defines allowed tags.
  • Declarative Nature: Specifies what, not how.
  • Strict Structure: Proper opening/closing tags required.
  • Supports complex data.
Drawback: Too complex, hard to implement → led to simpler languages.

Evolution of HTML

  • Created by Tim Berners-Lee.
  • Based on SGML but made simpler & forgiving.

Versions

  • HTML 2.0 & 4.0: Tried to follow SGML, limited by backward compatibility.
  • HTML5: Broke away from SGML, defined its own rules.

XML (Extensible Markup Language)

  • Simplified version of SGML.
  • Flexible + structured.

Features

  • Human-readable.
  • Machine-readable.
  • Custom tags allowed.

Applications

  • RSS Feeds → Website updates.
  • SVG → Graphics (shapes like circles, rectangles).
  • Documents: .docx, .odt = zipped XML files.

XML vs JSON

  • JSON: Simpler, widely used.
  • XML: More structured, better parsing.

XHTML & HTML5

XHTML

  • HTML reformulated using XML rules.
  • Very strict, hard to extend.

HTML5

  • Supports video, audio, graphics (canvas).
  • Easy to use.
  • Living Standard: Maintained by WHATWG, continuously updated.

Software-Defined Extension

JavaScript Integration

  • Add custom elements (new tags) using JavaScript.
  • Makes web apps more powerful.

Semantic Challenge

  • Custom tags may confuse search engines.
  • Standard tags (like <h1>, <title>) are important for:
    • SEO.
    • Page understanding.

Quick Summary

  • Markup = structure + meaning.
  • SGML = base (complex).
  • HTML = simplified, widely used.
  • XML = flexible, structured.
  • HTML5 = modern, evolving.
  • JavaScript extends HTML functionality.
  • Use standard tags for clarity + SEO.

Lecture 2: JavaScript

Introduction

  • JavaScript (JS): High-level programming language for the web.
  • Similar to Python (dynamic), but not the same as Java.
  • Role: One of the three pillars of the web → HTML, CSS, JavaScript.

Core Characteristics

  • High-Level Language: No need to manage memory or pointers.
  • Dynamic Typing: Data type decided at runtime.
  • Object-Oriented (Prototype-based): Uses prototypes instead of traditional classes.
  • Built-in Data Structures:
    • Arrays (lists).
    • Objects (key-value pairs like dictionaries).
    • Can build trees, graphs.
  • Browser-Native: Runs directly inside web browsers.

Programming Paradigms

  1. Imperative: Step-by-step execution of instructions.
  2. Functional:
    • Functions are first-class objects.
    • Can be stored in variables, passed as arguments, returned from functions.
  3. Event-Driven (Most Important):
    • Code runs based on events (click, hover, input).

Role in Web Development

DOM (Document Object Model)

  • Interface to interact with HTML.
  • Allows modification of content, updating styles, adding/removing elements.
  • No page reload needed.

APIs Instead of Native I/O

  • No direct file/system access.
  • Uses browser APIs for:
    • Dates.
    • Strings.
    • Pattern matching.

Syntax & Programming Basics

  • Variables:
    • const → cannot change.
    • let → block-scoped variable.
    • var → old method (avoid).
  • Functions:
    • Defined using function keyword.
    • Anonymous functions: no name, used directly.
      • Example: button.onclick = function() { ... }
  • Operators & Logic:
    • Arithmetic: + - * /
    • Conditions: if...else
  • Comments:
    • Single-line → //
    • Multi-line → /* */

Practical Tools

  • Document Querying: document.querySelector() → select HTML elements using ID, tag, class.
  • Event Listeners: addEventListener() → attach actions to events.
    Example: button.addEventListener("click", function() { ... });
  • Debugging Tools:
    • Browser Developer Tools (F12).
    • Inspect HTML, debug JS, see live changes.

Learning Resource

  • Mozilla Developer Network (MDN): Most trusted resource for web development.

Quick Summary

  • JS = dynamic, high-level, browser-based language.
  • Supports imperative, functional, and event-driven paradigms.
  • DOM → controls webpage dynamically.
  • Uses APIs (no direct I/O).
  • Key tools: querySelector, addEventListener.
  • Debug using browser developer tools.

Lecture 3: Custom Elements

Why JavaScript in HTML?

  • Purpose: To create custom elements (new HTML tags).
  • Limitation of HTML5: Only predefined tags allowed (e.g., <h1>, <title>).
  • Cannot directly create new tags like <my-button>.
  • Solution: Use JavaScript to define:
    • How the element looks.
    • How it behaves.

Problem of Interpretation

  • Browsers do not understand custom tags by default.
  • JavaScript provides:
    • Rendering logic: What appears on screen.
    • Behavior definition: How the element acts.

State Management

  • Elements can have internal states.
  • Example: Checkbox → checked/unchecked.
  • Custom elements can also maintain their own states using JavaScript.

Types of Custom Elements

Autonomous Custom Elements

  • Completely new elements.
  • Not based on existing HTML tags.
  • Example: <flag-icon>

Customized Built-in Elements

  • Extend existing HTML elements.
  • Example: Extend <p> to add word count feature.

Web Components (Three Pillars)

  1. Custom Elements API → Used to define new HTML tags.
  2. Shadow DOM → Provides encapsulation, keeps styles isolated, prevents CSS conflicts.
  3. HTML Templates →
    • <template> → reusable structure.
    • <slot> → dynamic content insertion.
    • Helps create reusable UI parts.

Implementation & Standards

  • HTML Living Standard: Maintained by WHATWG, continuously evolving.
  • Non-Normative Sections: Some parts are not fixed and may change.

JavaScript Definition: Create a class extending HTMLElement.
Register using: customElements.define('tag-name', ClassName);

Rendering

  • Class defines:
    • What to display.
    • How it updates.

Reusability & Benefits

  • Encapsulation: Shadow DOM → self-contained components.
  • Reusability: Components can be reused across projects, shared via files or platforms like GitHub.
  • Widgets: Main goal → build reusable UI components.
    • Examples: Buttons, cards, custom inputs.

Standardization Challenges

  • API is standardized.
  • Implementation styles vary.
  • Developers may use different Shadow DOM patterns or template structures.

Quick Summary

  • Custom elements = new HTML tags using JavaScript.
  • Browser needs JS to understand custom tags.
  • Two types: Autonomous and Customized built-in.
  • Web Components = Custom Elements + Shadow DOM + Templates.
  • Shadow DOM = style isolation.
  • Highly reusable and modular.

Lecture 4: Frameworks

Definition

  • Framework: A ready-made structure that helps build applications without starting from scratch.

Why Frameworks?

  • Remove Boilerplate Code: Avoid repeating common setup code.
  • Avoid Reinventing the Wheel: Provides standard solutions to common problems.
  • Consistency: Same structure and practices across projects.
  • Distilled Experience: Based on years of developer knowledge, similar to design patterns (like MVC).

Single Page Applications (SPAs)

  • Definition: Web app runs on one single page.
  • How it works: Updates content using JavaScript in the background.

Benefits

  • Faster user experience.
  • No full page reloads.
  • Feels like a desktop/mobile app.

React (Case Study): Developed by Meta Platforms

Key Features

  • Declarative Approach: Define what UI should look like, not how to build it.
  • Components: UI broken into small reusable parts; each manages its own logic.
  • Instant Rendering: Updates happen instantly in browser, no reload needed.
  • Stateful Components: Components can store internal data (state).
    • Example: Timer, input field.
  • Encapsulation: Each component is self-contained.
    • Examples: To-do list, Markdown editor.

Popular Frameworks Overview

  • React: Most popular, UI-focused.
  • Angular: Full-featured, component-based.
  • Vue.js: Simple, lightweight alternative.
  • Ember.js: Includes routing + services.
  • Flask: Backend framework (Python).

Modern Web Development Stack

  • The "Triple Threat":
    • HTML → Structure.
    • CSS → Styling.
    • JavaScript → Logic.

HTML5 as Living Standard: Continuously updated, no major version jumps.

Role of JavaScript

  • Acts as adaptation layer.
  • Handles dynamic updates and user interaction.
  • Reduces server dependency → faster apps.

Frameworks as Gap Fillers

  • Raw HTML + CSS + JS can be messy.
  • Frameworks:
    • Remove boilerplate.
    • Provide structure.
    • Suggest best practices.

Quick Summary

  • Framework = pre-built structure for apps.
  • SPAs = fast, no page reloads.
  • React = component-based, declarative UI.
  • Popular tools: React, Angular, Vue, Flask.
  • Web stack = HTML + CSS + JavaScript.
  • Frameworks simplify development and improve consistency.
