Lecture 1: Automating Scripts

What is Linux Automation?

  • Running tasks automatically without human intervention.
  • Instead of manually executing scripts, Linux can schedule them.
  • Helps in system maintenance, backups, log management, monitoring.

Why Automation is Important

  • Saves time for administrators.
  • Reduces errors.
  • Ensures tasks run regularly.
  • Improves system reliability.
  • Supports 24/7 server operation.

The crond Daemon

  • Background service that runs continuously.
  • Checks system clock, monitors scheduled tasks, executes scripts.
  • Acts as the scheduler of Linux.

Common Uses of Cron

  • Log rotation → archives old logs, prevents disk full.
  • System backups → automatic redundancy.
  • Resource cleanup → deletes temp files.
  • Monitoring & alerts → sends health notifications.

Crontab (Cron Table)

  • File where scheduled tasks are defined.
  • Edit with: crontab -e
  • Types:
    • System crontab (/etc/crontab) → requires user field.
    • User crontab (crontab -e) → no user field.

Format

Minute Hour Day_of_Month Month Day_of_Week Command

Example: 30 2 * * * /home/user/backup.sh → runs daily at 2:30 AM.

Field Ranges

FieldRange
Minute0–59
Hour0–23
Day1–31
Month1–12
Weekday0–6 (Sunday=0)

Useful Scheduling Symbols

  • Every day → * * * * *
  • Every hour → 0 * * * *
  • Every 10 minutes → */10 * * * *
  • Weekdays → 0 9 * * 1-5
  • Sunday → 0 3 * * 0

Defensive Automation

27 * * * * cd /home/scripts/backup && ./mkbackup.sh

&& ensures script runs only if cd succeeds.

Run Levels (System States)

Run LevelPurpose
0Shutdown
1Single-user mode
2–4Multi-user modes
5Multi-user with GUI
6Reboot

Scripts stored in: /etc/init, /etc/init.d, /etc/rcN.d.

Creating a Cron Job

  • Create script → mkbackup.sh
  • Make executable → chmod +x mkbackup.sh
  • Schedule → crontab -e
  • Verify execution → cat mkbackup.log

Logging Best Practice

  • Append (>>) → preserves history.
  • Overwrite (>) → erases old logs.

System-wide Cron Directories

DirectoryExecution Time
/etc/cron.hourly17th minute of every hour
/etc/cron.daily6:25 AM daily
/etc/cron.weekly6:47 AM Sunday

Managed by anacron. Times staggered to avoid CPU spikes.

Important Commands

  • Edit crontab → crontab -e
  • View crontab → crontab -l
  • Make script executable → chmod +x script.sh
  • View logs → cat logfile

Quick Revision

  • crond = background daemon.
  • crontab = scheduling file.
  • User crontab → 5 fields.
  • System crontab → 6 fields.
  • * = every value.
  • */10 = every 10 minutes.
  • && = safe execution.
  • >> = append logs.
  • Run level 5 = GUI.
  • Run level 6 = reboot.
  • /etc/cron.daily → 6:25 AM.
  • Staggered timings reduce load.

Lecture 2: Stream Editor (sed)

What is sed?

  • Command-line text processing tool.
  • Used to search, replace, delete, insert, and modify text automatically.
  • Processes text line by line (does not load entire file).
  • Common uses: text replacement, data cleaning, log processing, automation scripts, preprocessing before awk.

Why sed is Important

  • Very fast.
  • Works well with pipelines.
  • Automates text editing.
  • Available on almost all Unix/Linux systems.
  • POSIX compatible.
  • GNU sed adds features like sed -E (Extended Regex).

sed Working Model

  • Processes one line at a time.
  • Two memory areas:
    • Pattern space → current line, commands applied here.
    • Hold space → temporary storage for multi-line processing.

Execution Cycle

  • Read line into pattern space.
  • Execute commands.
  • Print pattern space (default).
  • Read next line.
  • Repeat until EOF.

Basic Syntax

  • One command: sed 'command' file.txt
  • Multiple commands: sed -e 'cmd1' -e 'cmd2' file.txt
  • External script: sed -f script.sed file.txt

Tip: Always use single quotes ' ' around commands.

sed 's/apple/orange/' file.txt

TypeExample

Common Action Commands

  • Print (p): sed -n '5p' file.txt
  • Delete (d): sed '/error/d' log.txt
  • Substitute (s): sed 's/cat/dog/' file.txt
    • Global: sed 's/cat/dog/g' file.txt
    • Extended regex: sed -E 's/(cat|dog)/animal/' file.txt
  • Line number (=): sed '=' file.txt
  • Comments (#): Used in sed scripts.

Structural Modification Commands

  • Insert (i): sed '3i\New Header' file.txt
  • Append (a): sed '3a\New Footer' file.txt
  • Change (c): sed '3c\Updated Line' file.txt

Data Cleaning Example

  • Remove unwanted lines: /Roll[0-9]+/!d
  • Normalize spaces: s/ */ /g
  • Remove leading noise: s/^.*(Roll[0-9]+)/\1/

Result → clean structured data.

sed as a Programming Language

  • Supports labels and branching.
  • Labels: :start
  • Branch (b): b start
  • Conditional branch (t): executes if substitution succeeded.
  • Failed branch (T): executes if substitution failed.

Multi-line Processing

  • N: appends next line to pattern space.
  • Example: joining lines ending with \.

Script:

:top
/\\$/ {
N
s/\\\n//
b top
}

Hold Space Operations

  • Store previous lines.
  • Swap data.
  • Reverse order.
  • Multi-line comparisons.
  • Command: x (exchange pattern & hold space).

Important Flags

FlagPurpose
-nSuppress automatic printing
-EExtended regex
-eAdd command expression
-fRead commands from file
--debugDebug complex scripts

Best Practices

  • Use single quotes.
  • Use -E for cleaner regex.
  • Use -n with p.
  • Test with --debug.
  • Avoid infinite loops with branches.

sed vs awk

Best for text editingBest for data processing

Quick Revision

  • sed = stream editor.
  • Processes line by line.
  • Pattern space & hold space.
  • Default = print every line.
  • -n suppresses printing.
  • p = print, d = delete.
  • s/// = substitute, g = global.
  • i = insert, a = append, c = change.
  • N = append next line.
  • :label + b = loop.
  • t = branch after success.
  • -E = extended regex.
  • --debug = trace scripts.
