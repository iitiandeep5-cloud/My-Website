Lecture 1: Version Control — Part 01

Version Control Basics

  • Definition: Tracks changes in code and maintains different versions.
  • Save Point Analogy: Like checkpoints in a game.
  • Importance: Backup/Safety, History, Revert, Collaboration, Traceability.

Modular Programming

  • One file → one function/class/module
  • Advantages: Conflict Minimization, Clear Division of Work, Easy Maintenance

Build Automation — make

  • make recompiles only changed files.
  • Benefit: Saves time, avoids unnecessary compilation.

Centralized vs Distributed Version Control

FeatureSVNGit
ArchitectureCentralizedDistributed
Offline workLimitedStrong support
RedundancyBackupsBuilt-in
BranchingSupportedVery powerful

RAID — Hardware Redundancy

  • RAID = Redundant Array of Independent Disks
  • Goals: Fault Tolerance, Performance, Capacity

RAID Levels

  • RAID 0: Striping, speed, no redundancy
  • RAID 1: Mirroring, safety, half usable capacity
  • RAID 5: Striping + parity, tolerates 1 disk failure
  • RAID 6: Extra parity, tolerates 2 disk failures

Other Concepts

  • RAID Controller — manages striping/mirroring/parity
  • Hot Spare — standby disk for auto-replacement
  • Capacity Overhead — redundancy reduces usable space

GitHub & Security

  • GitHub = Remote hosting + collaboration
  • Features: Pull Requests, Issue Tracking, Access Control

Security

  • 2FA — password + second factor
  • PAT — token-based authentication
    • Granular permissions
    • Revocable
    • Safer than passwords

Git CLI Workflow

Clone → Change → Add → Commit → Push

  • git clone — copy remote repo
  • git init — create repo in directory
  • git remote add origin — connect local to remote
  • git add — stage changes
  • git commit — record changes locally
  • git push — send commits to remote

Revision

  • Version Control → Tracks versions, revert anytime
  • Git vs SVN → Distributed vs centralized
  • RAID → 0 = Speed, 1 = Mirror, 5 = 1 failure, 6 = 2 failures
  • GitHub Security → 2FA + PAT
  • Workflow → Clone → Add → Commit → Push

Lecture 2: Version Control — Part 02

Why Security Matters

  • Source Code Protection: Contains project logic, IP, credentials, private company info.
  • Password Alone Not Enough → Modern authentication uses MFA/2FA.

GitHub Password Authentication Change

  • Since Aug 13, 2021, GitHub stopped accepting passwords for Git over HTTPS.
  • Use Personal Access Tokens (PATs) or other supported methods.

Two-Factor Authentication (2FA)

  • 2FA = Password + Second Factor.
  • Protects accounts even if password leaks.

Methods

  • Authenticator App → Strong choice, local codes, reliable.
  • SMS → Possible delays, requires correct country code (India = +91).

Recovery Codes

  • Backup access if phone/authenticator unavailable.
  • Best Practice: Save securely, never commit/share.

Repository Architecture

  • Public Repository → Anyone can view/clone, only authorized users push.
  • Private Repository → Restricted access.

Personal Access Token (PAT)

  • Credential for GitHub operations.
  • Advantages: Limited permissions, revocable, replaceable, purpose-specific.

Creating PAT

  • GitHub → Settings → Developer Settings → Personal Access Tokens → Create Token.
  • Name tokens meaningfully (e.g., July-13-Repo).
Protecting PAT: Never commit/share/upload PATs. Example danger: git add . accidentally stages PAT.txt. Safer storage: Credential managers, helpers, environment variables.

Git Identity

git config --global user.name "Your Name"
git config --global user.email "your@email.com"

Creates audit trail of commits.

Git Workflow: Check → Add → Commit → Push

  • git init → Create repo (.git directory).
  • git status → Diagnostic, check before staging.
  • git add → Stage changes (specific file preferred).
  • git commit → Local snapshot.
  • git push → Send commits to remote.

Branching & Pull Requests

  • Branch = Separate line of development.
  • Example: main → panda (feature branch).
  • First Push: git push --set-upstream origin panda.
  • Pull Request → Review, merge into main.
  • Merge Conflicts → Manual resolution required.
  • Delete Feature Branch → Avoid branch bloat.

Security Practices

  • git rm --cached → Stop tracking sensitive files.
  • .gitignore → Prevent staging of secrets/logs/temp files.
  • mv PAT.txt .. → Move secrets outside repo.
  • If exposed → Revoke/rotate immediately.

Common Errors

  • Authentication Failure → Expired/revoked PAT, wrong permissions, cached credentials.
  • Upstream Error → Fix with git push --set-upstream origin branch.

Complete Git Workflow

  • Setup: git init, config identity, connect remote.
  • Daily Dev: git status → git add → git commit → git push.
  • Feature Work: Create branch, push, PR, merge, cleanup.

Lecture 3: Knowing Your Hardware

Hardware Discovery — Why?

  • Definition: Identify and analyze system hardware.
  • Why important: Troubleshooting, performance optimization, upgrades, virtualization, server planning.
  • Easy idea: Hardware discovery = knowing CPU, RAM, disks, GPU, PCI devices, battery, network.

Installing Tools

  • hwinfo / lshw → General hardware inventory.
  • pciutils / dmidecode → PCI + RAM info.
  • hdparm / sysstat → Disk + I/O monitoring.
  • clinfo → GPU/OpenCL info.
  • upower → Battery/power info.
  • net-tools → Legacy networking (ifconfig).

Recording Hardware Info

  • Save outputs: hwinfo --short > hardware_baseline.txt.
  • Benefits: Compare machines, keep baseline, share diagnostics.
  • GUI vs CLI: GUI (hardinfo) = overview; CLI = scriptable, remote-friendly.

Key Tools

  • hwinfo → Broad probing.
  • lshw → Hierarchical view.
  • Memory trick: hwinfo = lots of info, lshw = organized hierarchy.

CPU & Memory

  • cat /proc/cpuinfo → CPU details + flags.
  • CPU flags → Show supported features (virtualization, crypto).
  • Cache → Fast memory near CPU; reduces RAM fetches.
  • free -h → RAM + swap usage.
  • Swap → Disk as memory extension (slower). Not always 2× RAM.
  • dmidecode → RAM modules, BIOS, motherboard info.
  • DIMM vs SODIMM → DIMM = desktop/server, SODIMM = laptop/compact.

Storage

  • lsblk → Block devices tree.
  • /proc/partitions → Kernel partition info.
  • hdparm → Disk benchmark.
  • SATA HDD vs SSD → HDD slower (~127 MB/s), SSD faster.
  • RAID → Striping improves throughput.
  • Cached vs actual read → Don't confuse cache speed with real disk speed.
  • Units: MB/s vs Mb/s (bytes vs bits).
  • iostat → CPU + I/O monitoring, detect I/O-bound workloads.

PCI & GPU

  • lspci → List PCI/PCIe devices.
  • GPU types: Integrated (basic graphics), Dedicated (high-performance compute).
  • clinfo → OpenCL device info.

Power & Battery

  • upower -e → List devices.
  • upower -i → Detailed battery info.
  • Battery health = Full Charge ÷ Design Capacity × 100.
  • Replacement threshold ~30–40% design capacity (lecture example).
  • Time to empty → Dynamic, workload dependent.

Networking

  • ifconfig → Legacy interface info.
  • ip addr → Modern alternative.
  • Loopback → 127.0.0.1 = this computer itself.
  • Troubleshooting flow: Hardware → Interface → IP → Gateway → Network → Internet.

Lecture 4: Prompt String

Command-Line Prompt

  • CLI prompt = text/symbol shown when shell is ready for input.
  • Provides environment info: Username, Hostname, Current directory, Privilege (normal/root)
  • A changed prompt may indicate shell configuration changes or special environments.

Common Linux Shells: Bash, Dash, Zsh, Ksh, Csh

Bash Prompt Variables

VariableMeaningWhen it AppearsDefault
PS1Primary PromptNormal command input$ / #
PS2Secondary PromptMore input required>
PS3Selection PromptInside select loop#?
PS4Trace PromptDebugging with set -x+
  • PS1 → Normal prompt (user@computer:~$)
  • PS2 → Appears when command incomplete (>).
  • PS3 → Used in select loops.
  • PS4 → Used for debugging (set -x).

Bash Prompt Escape Sequences

User & Machine

  • \u → Username
  • \h → Hostname (short)
  • \H → Full hostname

Date & Time

  • \t → 24-hour time
  • \T → 12-hour time
  • \d → Date

Directory & History

  • \w → Full path
  • \W → Current directory name
  • \# → Command number

Example: PS1="\u@\h:\w\$ " → user@computer:/home/user$

Default Ubuntu Prompt

  • Format: \u@\h:\w\$
  • Example: student@ubuntu:/home/student$
  • $ → normal user, # → root user

ANSI Color Codes

  • Example: \033[01;32m → color formatting.
  • Difference:
    • Functional sequences (\u, \h, \w) → system info.
    • ANSI sequences → visual formatting.

Why Use \#

  • Shows command number in session.
  • Useful for debugging, tracking, and history.

Making Prompt Changes Permanent

  • Temporary change: PS1="..."
  • Permanent change: edit ~/.bashrc

Best Practice: Comment out old config instead of deleting.

Apply .bashrc Changes Immediately

  • Use: source ~/.bashrc

  • Bash → prompt variables + escape sequences.
  • Python → programmatically customizable.

Best Practices for Designing a Prompt

  • Show user (\u)
  • Show host (\h)
  • Show directory (\w)
  • Use PS4 for debugging (set -x)
  • Save changes in .bashrc

Lecture 5: Managing Storage

Storage Architecture — Basic Idea

  • Modern storage = multiple disks managed as one system.
  • RAID → speed + redundancy + fault tolerance.
  • LVM → flexibility + logical storage management.
  • Flow: Physical Disks → RAID → Storage Pool → LVM → Logical Volume → File System → User.

LVM (Logical Volume Management)

  • Combines multiple physical disks into one logical volume.
  • Hides physical complexity.
  • Benefits: flexible, large logical volumes, easier management.
  • Implemented via lvm2 package in Linux.

RAID (Redundant Array of Independent Disks)

  • Combines disks for performance, redundancy, fault tolerance.
  • Disk failure is inevitable → RAID reduces impact.
  • Types: Hardware RAID (controller) vs Software RAID (OS).
  • Supports hot swapping (replace failed disk while system runs).

RAID Levels

RAIDPurposeMin DisksFault Tolerance
RAID 0Speed, capacity20
RAID 1Mirroring21 disk
RAID 5Single parity31 disk
RAID 6Double parity42 disks

Memory Trick: RAID 0 → 0 protection, RAID 1 → 1 disk, RAID 5 → 1 disk, RAID 6 → 2 disks.

RAID 0

  • Striping → max speed & capacity.
  • No fault tolerance.
  • If one disk fails → all data lost.

RAID 1

  • Mirroring → redundancy.
  • Survives 1 disk failure.
  • Storage efficiency = 50%.

RAID 5

  • Distributed parity.
  • Survives 1 disk failure.
  • Good balance of speed + protection.

RAID 6

  • Double parity.
  • Survives 2 disk failures.
  • Better for large arrays.

LVM vs RAID

  • LVM → logical storage flexibility.
  • RAID → redundancy + performance.
  • Together: RAID protects, LVM organizes.

Enterprise Storage Examples

  • Intel Dev Cloud → ~1 PB storage.
  • IIT Madras Supercomputer → ~1 PB with /lfs mount points.
  • Synology NAS → tens of TB via RAID.

Parallel File Systems

  • Many devices → huge storage → single mount point.
  • Example: /lfs directory hides complexity.

Mount Point

  • Logical directory to access storage.
  • User sees /lfs but behind it → RAID + LVM + disks.

Advantages of LVM + RAID

  • Cost-effective → combine smaller drives.
  • Resilient → survive disk failures.
  • Convenient → users see one mount point.

Key Terms

  • LVM → Logical Volume Management.
  • RAID → Redundant Array of Independent Disks.
  • Striping → RAID 0.
  • Mirroring → RAID 1.
  • Parity → RAID 5/6.
  • Hot Swap → replace disk live.
  • Logical Volume → unit created by LVM.
  • Mount Point → directory for storage.
  • Fault Tolerance → survive failures.

Revision

  • LVM → flexibility, logical volumes, lvm2 package.
  • RAID → redundancy, performance, fault tolerance.
  • RAID 0 → fast, no protection.
  • RAID 1 → mirror, 1 disk failure.
  • RAID 5 → single parity, 1 disk failure.
  • RAID 6 → double parity, 2 disk failures.
  • Flow: Physical Disks → RAID → LVM → File System → Mount Point → User.
Final Memory Trick: RAID = speed + protection. LVM = logical flexibility. File system = usable files & directories.
