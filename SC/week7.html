Lecture 1: Bash Scripts — Part 2A

Script Debugging (Execution Transparency)

Why Debugging? Helps find errors while the script is running. Shows how Bash executes each command. Useful for debugging loops, conditions, and variables.

  • Enable Debugging: set -x
  • Disable Debugging: set +x
set -x
echo "Debugging starts"
set +x
  • Output Indicator: Commands prefixed with + when debugging is ON.
    Example: + echo Hello → Hello
  • Note: + comes from the PS4 environment variable. Use set -x only around the code you want to debug.

Advanced Control Flow

  • Logical Operators:
    • && → AND (both conditions true)
      Example: if [[ $x -gt 3 && $x -lt 7 ]]
    • || → OR (at least one condition true)
      Example: if [[ $x -le 3 || $x -ge 7 ]]
  • Nested Structures: Control structures can be inside one another (e.g., for → while → if).
  • Best Practice: Use proper indentation.

Arithmetic in Bash

Method 1: let

let "c=a+b"

Quotes required if spaces are used.

Method 2: Square Brackets (Deprecated)

echo $[5+6]

Method 3: expr

c=$(expr $a + $b)

Method 4: Double Parentheses (Recommended)

((sum=a+b))
((count++))

Comparison Table

MethodSyntaxNotes
letlet "a=b+c"Wrapper command
$[]$[a+b]Old/Deprecated
exprexpr $a + $bStandalone command

expr Command

  • Capabilities: Arithmetic, Comparisons, Logical operations, String operations.
  • Operators:
    • Arithmetic: + - * / %
    • Comparison: > >= < <= == !=
    • Logical: | (OR), & (AND)
  • Escape Characters: Must escape * > < | &
    Example: expr 5 \* 4

String Manipulation with expr

  • Regex Match: expr string : regex → Anchored matching (BRE).
  • Substring: expr substr Linux 2 3 → Output: inu
  • Index: expr index version0.1s js → Output: 12
  • Length: expr length Linux → Output: 5

Limitation: BRE does not support + quantifier.

Floating Point Calculations with bc

  • Bash Limitation: No decimal calculations.
  • Use bc:
result=$(bc -l <<EOF
scale=4
(12+6)^2
EOF
)
echo $result
  • Output: 324.0000
  • scale: Controls decimal precision. Example: scale=3 → 3 decimal digits.
  • Here Document: <<EOF ... EOF (marker can vary). <<-EOF ignores leading tabs.

PATH Variable Parsing using IFS

IFS (Internal Field Separator): Default → Space, Tab, Newline.

Parsing PATH:

OLDIFS=$IFS
IFS=':'
count=0
for dir in $PATH
do
    echo "Directory $count : $dir"
    ((count++))
done
IFS=$OLDIFS
  • Why Save IFS? To restore original environment later.
  • Example PATH: /bin:/usr/bin:/usr/local/bin → Split into directories.

Quick Revision

  • Debugging: set -x / set +x, PS4 prefix.
  • Logical Operators: && (AND), || (OR).
  • Arithmetic: let, $[] (deprecated), expr, (( )) (best).
  • expr: Arithmetic, Comparison, Logical, String ops. Escape special chars.
  • String Functions: Regex match, substr, index, length.
  • bc: Decimal calculations, scale for precision, Here Document.
  • IFS: Save/restore, change to : for PATH parsing.

Lecture 2: Bash Scripts — Part 2B

Multi-Level Conditional Branching (if – elif – else)

Why Use It? Used when there are multiple possible conditions, not just True/False. Bash checks conditions from top to bottom. As soon as one condition becomes true, it executes that block and skips the rest.

if [ condition ]; then
    commands
elif [ condition ]; then
    commands
elif [ condition ]; then
    commands
else
    commands
fi
  • Execution Flow: if → elif → elif → else → fi. Only one block is executed.
  • Condition Order Rule: Always write conditions from Most Specific ➜ Most General.

Example (Argument Count)

if [ $# -gt 2 ]; then
    echo "More than sufficient"
elif [ $# -gt 1 ]; then
    echo "Sufficient"
elif [ $# -gt 0 ]; then
    echo "Not sufficient"
else
    echo "No arguments"
fi

Special Variable: $# → Returns number of command-line arguments.

Case Statement

Why Use case? Cleaner alternative to multiple if – elif. Best for string/pattern matching.

case $variable in
    pattern1)
        commands ;;
    pattern2)
        commands ;;
    *)
        commands ;;
esac

Important Keywords

KeywordPurpose

inBegin patterns
)Ends pattern

  • Multiple Patterns: gimp | inkscape) → Matches either.
  • Wildcard: * → Default case.
  • Character Matching: [Aa]dobe* → Matches Adobe/adobe variations.
case $INPUT in
    gimp | inkscape)
        echo "Open-source editor" ;;
    [Aa]dobe*)
        echo "Commercial software" ;;
    "image j")
        echo "Matrix tool" ;;
    *)
        echo "Unknown Program" ;;
esac

C-Style For Loop

Definition: Bash extension similar to C language. Works only in #!/bin/bash.

for ((initialization; condition; increment))
do
    commands
done

Example:

for ((i=1;i<=5;i++))
do
    echo $i
done

Multiple Variables:

for ((a=1,b=20; a<20; a++,b--))
do
    echo $a $b
done

Exponentiation: echo $((5**2)) → Output: 25

Redirect Entire Loop Output

for ((i=1;i<=5;i++))
do
    echo $i
done > output.txt

Prevent File Overwrite:

if [ -f "$FILE" ]
then
    echo "File exists"
    exit 1
fi
  • File Test Operator: -f → Checks if file exists.
  • exit: exit 1 → Terminates script with error.
  • Process ID: $$ → Current script PID. Useful for unique temp files.

Large File Example

for ((i=1;i<=10000;i++))
do
    echo "$i $((i+1))"
done > data.txt

Break and Continue

break: Stops loop immediately.

for ((i=1;i<=10;i++))
do
    if [ $i -eq 5 ]; then
        break
    fi
    echo $i
done
  • break Levels: break → Current loop. break 2 → Stops two nested loops.

continue: Skips current iteration.

for ((i=1;i<=10;i++))
do
    if [ $i -ge 3 ] && [ $i -le 7 ]; then
        continue
    fi
    echo $i
done

Difference Table

breakcontinue
Stops loopSkips current iteration
Loop endsLoop continues

Shift Command

  • Purpose: Processes command-line arguments one by one.
  • Effect: Moves arguments left. $1 discarded, $2 becomes $1, etc.
  • Argument Count: $# decreases after each shift.
while [ $# -gt 0 ]
do
    echo $1
    shift
done

exec Command

  • Purpose: Replaces current shell process with another program. No child process created.
  • Normal Command: Returns to script after execution.
  • exec Command: Script disappears if exec succeeds.
  • PID: New program keeps same PID.

Error Handling Example:

echo "Launching..."
exec xterm
echo "Launch Failed"

Quick Revision

  • If-Elif-Else: Multi-condition branching, order matters, ends with fi.
  • Case: Cleaner than multiple elif, ends with esac, supports patterns.
  • C-Style For Loop: Bash-only, supports multiple variables, ** for power.
  • File Redirection: Redirect whole loop with done > file.txt.
  • File Test: -f checks file existence.
  • exit: Stops script.
  • $$: Current PID.
  • break/continue: Stop loop vs skip iteration.
  • shift: Processes arguments sequentially, destructive.
  • exec: Replaces process, script ends unless exec fails.

Lecture 3: Bash Scripts — Part 3

eval Command (Dynamic Command Execution)

  • Definition: eval is used to create and execute commands dynamically. It combines strings into a complete command and executes them as if typed directly in the terminal.
  • Syntax: eval command

How eval Works:

cmd="date"
fmt="+%Y-%m-%d"
eval $cmd $fmt

Step 1: Variables → cmd=date, fmt=+%Y-%m-%d
Step 2: Combined → date +%Y-%m-%d
Step 3: Executed → Output: 2026-07-27

  • Why Use eval? Builds commands at runtime, useful for dynamic scripts.
  • Process ID (PID): Runs in the same shell, no subshell created. PID remains unchanged.
Security Warning: Never use raw user input with eval. Example: eval "$cmd" with user input rm -rf / → Dangerous. Safe practice: Use only internally created commands.

Functions (Modular Programming)

Purpose: Functions allow code reuse, reduce repetition, and improve readability.

Syntax:

function_name() {
    commands
}

or

function function_name {
    commands
}

Example:

swap() {
    echo "$2 $1"
}
swap Hello World
# Output: World Hello

Function Arguments

  • $1, $2, $3 → Arguments passed to function.
    Example: swap Apple Mango → Output: Mango Apple.

Usage Function Example

usage() {
    echo "Usage: $1 string1 string2"
}

if [ $# -lt 2 ]; then
    usage $0
    exit 1
fi

$0 → Script name. Automatically updates usage message if renamed.

External Function Libraries

  • Store functions in mylib.sh.
  • Import with: source mylib.sh or . mylib.sh

getopts (Command-Line Option Processing)

  • Purpose: Enables professional command-line options (ls -l, cp -r, etc.).
while getopts "abc:" opt
do
    case $opt in
    ...
    esac
done
  • Option String Example: "abc:" → a and b are flags, c: requires argument.
  • OPTARG: Stores value supplied to an option.
    Example: ./script.sh -c file.txt → OPTARG=file.txt.

Example:

while getopts "abc:" opt
do
    case $opt in
    a) echo "Option A" ;;
    b) echo "Option B" ;;
    c) echo "$OPTARG" ;;
    *) usage $0 ;;
    esac
done
  • Benefits: Options can appear in any order. Automatic error handling for invalid/missing options.

select Loop (Menu-Driven Programs)

  • Purpose: Creates numbered menus for interactive scripts.
select variable in item1 item2 item3
do
    commands
done

Example:

select i in {1..10}
do
    case $i in
    4|5|6|7) echo "Accepted"; break ;;
    *) echo "Choose 4,5,6 or 7" ;;
    esac
done
  • Features: Displays numbered menu automatically. Accepts only menu selections. Invalid selections ignored. Repeats until break.

Professional Bash Scripting Standards

  • Rule 1: Never give setuid permission to scripts → Security risk.
  • Rule 2: Never execute raw user input with eval.
  • Rule 3: Validate every input (numbers, filenames, options, empty values).
  • Rule 4: Use functions for reusable code.
  • Rule 5: Use external libraries (mylib.sh) for common functions.

Why Modular Programming?

  • Easier debugging.
  • Easy updates.
  • Code reuse.
  • Better organization.

Quick Revision

  • eval: Executes dynamic commands, same PID, unsafe with user input.
  • Functions: Reusable blocks, $1 $2 $3 for arguments, $0 for script name, external libraries via source.
  • getopts: Standard option processing, : means argument required, OPTARG stores value, automatic error handling.
  • select: Creates interactive menus, loops until break.
  • Professional Standards: Avoid setuid, validate input, modular design, external libraries.

One-Line Summary

  • eval: Executes dynamically built commands.
  • Functions: Make code reusable and modular.
  • source: Imports external function libraries.
  • getopts: Standard way to process command-line options.
  • select: Creates interactive terminal menus.
  • Professional Bash Scripts: Secure, modular, validated, maintainable.
