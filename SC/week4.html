Lecture 1: Pattern Matching — Part 01

POSIX Standard

  • BRE (Basic Regular Expression): default engine in grep, requires escaping for some symbols.
  • ERE (Extended Regular Expression): used with egrep or grep -E, simpler and more powerful syntax.

Grep Command Basics

  • Search in file: grep [pattern] [filename]
  • Pipe search: [command] | grep [pattern]
  • Case-insensitive: grep -i [pattern] [filename]
  • Best practice: use single quotes ' ' around regex.

Regex Meta-characters

  • Dot (.) → any single character.
  • Star (*) → zero or more occurrences.
  • Square brackets [ ] → any one character inside.
  • Hyphen (-) → range inside brackets.
  • Negation [^ ] → NOT inside brackets.
  • Backslash (\) → escape special characters.

Anchors & Boundaries

  • ^ → beginning of line.
  • $ → end of line.
  • \b → word boundary.

Repetition & Grouping

  • Braces {n,m}: define repetition count. BRE requires escaping: a\{2,4\}
  • Parentheses (): grouping. BRE requires escaping: \(ab\)
  • Back references: \1 \2 ... \9

Extended Regular Expression (ERE) Features

  • + → one or more occurrences.
  • ? → zero or one occurrence.
  • | → OR operator.
  • Simplified syntax: no escaping for () {}.

POSIX Character Classes

  • [[:alnum:]] → letters + digits
  • [[:alpha:]] → alphabet letters
  • [[:digit:]] → digits (0–9)
  • [[:space:]] → whitespace
  • [[:punct:]] → punctuation
  • [[:print:]] → printable characters
  • [[:lower:]] → lower case
  • [[:upper:]] → upper case
  • [[:blank:]] → space/tab
  • [[:xdigit:]] → hexadecimal
  • [[:graph:]] → non-space
  • [[:cntrl:]] → control characters

BRE Operator Precedence (High → Low)

  1. Character collation [..] [==] [::]
  2. Escaped (\) meta-characters
  3. [] bracket expressions
  4. \(\) \n subexpressions and backreferences
  5. * \{ \} repetition of preceding single char regex
  6. Concatenation
  7. Anchors (^ $)

ERE Operator Precedence (High → Low)

  1. Character collation [..] [==] [::]
  2. \ metachar
  3. [] bracket expressions
  4. () grouping
  5. * + ? { } repetition of preceding regex
  6. Concatenation
  7. Anchors (^ $)
  8. Alternation (|)

Quick Difference: BRE vs ERE

FeatureBREERE
Default grepYesNo
+ ?EscapedDirect
Parentheses\(\)()
Braces\{\}{}
Commandgrepgrep -E / egrep

Important Tips

  • Always use single quotes around regex.
  • BRE requires more escaping.
  • ERE is easier and more readable.
  • grep -E is preferred for advanced regex.

Lecture 2: Pattern Matching — Part 02

Advanced Pattern Matching with Grep

  • Use Extended Regular Expressions (ERE) with egrep or grep -E.
  • Useful for filtering outputs from commands like dpkg-query.

Fixed Length Matching

grep -E '^....$'

Matches lines with exactly 4 characters.

Line Anchors

  • End of Line ($): grep 'math$' → matches math but not mathematics.
  • Start of Line (^): grep '^math' → matches lines starting with math.

Field Targeting

grep ' package'

Targets specific fields by including a space.

Repetition Ranges

a{1,5}

Matches between 1 and 5 occurrences.

Character Classes (POSIX Style)

Syntax: [[:class:]]

ClassMeaning
[[:alpha:]]Alphabet letters
[[:alnum:]]Letters + digits
[[:digit:]]Numeric digits
[[:cntrl:]]Control characters
[[:punct:]]Punctuation marks
[[:lower:]]Lowercase letters
[[:upper:]]Uppercase letters
[[:print:]]Printable characters
[[:blank:]]Spaces/tabs
[[:graph:]]Visible non-space characters

Inversion Matching

  • grep -v '^$' → removes empty lines.
  • grep -v '[[:cntrl:]]' → removes lines with control characters.

Extracting Complex Patterns

Aadhar Number

[[:digit:]]{12}

PIN Code

\b[[:digit:]]{6}\b

Roll Number

[[:alpha:]]{2}[[:digit:]]{2}[[:alpha:]]{1}[[:digit:]]{3}

Example: CS21A123

URL Matching

[a-zA-Z0-9]+\.[a-zA-Z]+

Matches google.com, abc.org.

Horizontal Trimming with cut Command

  • Vertical trimming: head, tail
  • Horizontal trimming: cut

By Character (-c)

  • cut -c 1-4 → first 4 characters
  • cut -c 5- → from 5th character to end

By Field (-f) with Delimiter (-d)

cut -d ';' -f 1

Extracts first field before semicolon.

Combining Commands with Pipes

  • Pipes (|) connect commands for powerful workflows.

Multiple cut Commands

cut -d ';' -f 2 | cut -d ',' -f 1

Integrated Pipeline

cat file.txt | grep 'error' | cut -d ':' -f 2 | head -1

Workflow: read file → filter → extract field → print first match.

Important Tips

  • Use grep -E for advanced regex.
  • Anchors (^, $) ensure precise matching.
  • Character classes simplify complex patterns.
  • cut extracts structured fields.
  • Pipes combine commands effectively.
  • grep -v removes unwanted lines.

Lecture 3: What is find?

Introduction

The find command is used to:

  • Search files and directories.
  • Filter results using conditions.
  • Perform actions on matched files.
  • Recursively search subfolders by default.

Basic Syntax

Search current directory:

find .

Search specific directory:

find website_demo

Manual help:

man find

Filtering by Type

Directories only:

find . -type d

Files only:

find . -type f

Filtering by Name

Exact filename:

find . -type f -name "test1.txt"

Case-insensitive:

find . -iname "test1.txt"

Wildcard examples — files starting with "test":

find . -name "test*"

All Python files:

find . -name "*.py"

Filtering by Metadata

Time-Based Searches

Modified < 10 minutes:

find . -mmin -10

Modified > 10 minutes:

find . -mmin +10

Modified < 20 days:

find . -mtime -20

Other options:

OptionMeaning
-aminAccessed minutes ago
-atimeAccessed days ago
-cminChanged minutes ago
-ctimeChanged days ago

Combine ranges:

find . -mmin +1 -mmin -5

Size-Based Searches

  • Units: k (KB), M (MB), G (GB)
find . -size +5M

Permissions & File State

Empty files/dirs:

find . -empty

By permissions:

find . -perm 777

Limiting Search Depth

Restrict to current directory:

find . -maxdepth 1

Example:

find . -maxdepth 1 -type f

Executing Actions

Syntax:

find [path] [conditions] -exec [command] {} +

or

find [path] [conditions] -exec [command] {} \;
SymbolMeaning
{}Current matched file
+Batch execution
\;Execute per file

Examples — change ownership:

find website_demo -exec chown corey:www-data {} +

Change permissions:

find . -type d -exec chmod 775 {} +

Delete JPEG files:

find . -type f -name "*.jpeg" -maxdepth 1 -exec rm {} +

Best Practices

Always perform dry runs before destructive actions:

find . -type f -name "*.jpeg"

Then add -exec rm {} + only after verifying results.

Why dry runs matter: prevent accidental deletion, avoid permission mistakes, reduce risk of data loss.

Important Tips

  • find searches recursively by default.
  • Use -maxdepth to control recursion.
  • Combine filters for precision.
  • Always test before using -exec rm.
  • Wildcards (*) make searching flexible.
  • find is powerful when combined with other Linux commands.
