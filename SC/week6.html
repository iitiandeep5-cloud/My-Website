Lecture 1: Some Command Line Utilities

These commands help automate file management and are widely used by Linux/Unix administrators.

CommandPurpose
findSearch files/directories based on conditions
tarBundle multiple files/directories into one archive
gzipCompress files to save storage
makeRun commands only when required (conditional automation)

These tools are often combined in scripts for backup, cleanup, and maintenance.

find Command

Purpose: Search files/directories based on conditions.

Syntax: find [path] [conditions]

find . -name "*.txt"   # Search all .txt files in current directory and subdirectories

Common Conditions

  • -name → Search by filename
    Example: find . -name "*.c"
  • -type → Search by file type (f = file, d = directory, l = link, c = character device)
    Example: find . -type d
  • -atime → Search by last access time
    Example: find . -atime +30 (accessed more than 30 days ago)
  • -ctime → Search by last modification/change time
    Example: find . -ctime -7 (modified within last 7 days)
  • -size → Search by file size
    Example: find . -size +100M
  • -regex → Search using regex
    Example: find . -regex ".*\.txt"
  • -print → Print matching filenames
    Example: find . -name "*.txt" -print

-exec (Most Important)

Run a command on each matched file.

Syntax: find . [condition] -exec command {} \;

find . -name "*.log" -exec rm {} \;   # Deletes all .log files

Best Practice: Test with -print before using -exec.

tar Command (Archiving)

Purpose: Bundle files/directories into one archive (no compression).

Syntax: tar -cvf archive.tar directory

  • c → Create archive
  • v → Verbose (show files)
  • f → Archive filename
tar -cvf backup.tar project/

Note: tar only archives, does not compress.
Example: Folder size = 450 MB → backup.tar ≈ 460 MB (metadata overhead).

Compression Utilities

Compression saves disk space. Effectiveness depends on data repetition.

UtilityCompressionSpeedCPU/RAM
compressLowFastestVery Low
gzipMediumFastModerate
bzip2HighSlowHigh

Ratios

  • ASCII text: 100 MB → 10 MB (≈1:10)
  • Repetitive logs: 100 MB → 5 MB (≈1:20)

Usage

  • compress → Fastest, lowest compression
  • gzip → Best balance, standard choice
  • bzip2 → Highest compression, slower, more RAM

Portable formats: gzip, bzip2, xz, 7z

make Utility

Purpose: Automates tasks only when needed (compilation, backups, automation).

Makefile Structure

Target : Prerequisites
	Recipe

Example:

backup.tar: project
	tar -cvf backup.tar project
  • Target: File/action to create (e.g., backup.tar)
  • Prerequisites: Dependencies (e.g., project)
  • Recipe: Command to execute (must start with TAB)

Variables

  • := → One-time substitution
  • = → Recalculated every use
DATE := $(shell date)   # fixed once
DATE = $(shell date)    # recalculated each time

Intelligent Behavior

  • Compares timestamps before running commands.
  • Skips if source unchanged → saves CPU time.

Professional Workflows

  • Automated Cleanup: find to delete old temp files.
  • Timestamped Backup: make + tar → backup only if files changed.
  • Disk Optimization: gzip/bzip2 → reduce log size by 90%.
  • System Migration: tar + gzip → .tar.gz archives for transfer.

Quick Revision

  • find → Search files/directories
    • -name, -type, -atime, -ctime, -size, -regex, -print, -exec
  • tar → Archive only (no compression)
    • tar -cvf archive.tar folder
    • Options: c, v, f
  • gzip / bzip2 → Compression utilities
    • gzip → Balanced, fast
    • bzip2 → Highest compression, slower
    • Ratios: Text ≈1:10, Logs ≈1:20
  • make → Conditional automation
    • Structure: Target, Prerequisites, Recipe (TAB required)
    • Variables: := (once), = (every time)
    • Intelligent timestamp comparison

Lecture 2: Overview of Shell Scripts

Unix Philosophy

Linux follows the principle: "Small tools + Shell = Powerful Automation"

Core Principles

  • Do One Thing Well — Each command has a single job.
    Example: grep (search), sort (sort), wc (count).
  • Everything is Text — Data treated as text streams.
    Example: cat file.txt | grep "Linux"
  • Standard Input & Output — stdin → input, stdout → output.
    Example: ls | sort
  • User Combines Commands — Tools are simple; user decides combinations.
  • Don't Be Chatty — Commands should produce minimal output for clean piping.

Interpreted Languages in Linux

  • Common: Bash, awk, sed, Python, Perl, Ruby.
  • awk & sed: Installed by default, portable, no extra setup.

Script Anatomy

  • Shell Script: Text file containing commands.
  • Shebang (#!): Defines interpreter.
#!/bin/bash

PATH Environment Variable

  • Defines where Linux searches commands.
  • Example: /bin:/usr/bin:/home/user/bin
  • Best practice: Place scripts in leftmost PATH directory.

Symbolic & Hard Links

  • Scripts can be executed via links pointing to original file.

Login vs Non-Login Shell

Login ShellNon-Login Shell
Starts after login/SSHOpens inside GUI terminal
Reads login filesInherits parent environment
Fresh environmentUses existing environment

Files like .bash_profile and .bashrc control shell behavior.

Running a Script

1. Source Script

  • Syntax: source script.sh or . script.sh
  • Runs in current shell, same PID, variables persist.
  • Used for environment setup.

2. Execute Script

  • Syntax: ./script.sh
  • Runs in child shell, new PID, variables disappear.
  • Preferred for normal programs.

Difference: Source → Same shell, variables remain. Execute → Child shell, variables vanish.

Input & Output

  • echo → Simple output.
  • printf → Formatted output (preferred).
printf "Name: %s\n" "Rahul"

Command Substitution

DATE=`date`      # old
DATE=$(date)     # new (preferred)

Variables & Command-Line Arguments

  • $0 → Script name.
  • $# → Number of arguments.
  • $1, $2… → Arguments.
  • ${11} → 11th argument.
  • "$*" → All arguments as one string.
  • "$@" → Each argument separately (preferred).

Best Practice: Always use braces → ${name}

Flow Control

if Statement

if [ condition ]; then
    commands
fi

case Statement

case variable in
    pattern1) commands ;;
    pattern2) commands ;;
esac

Loops

  • for → Iterates list.
  • while → Runs while condition true.
  • until → Runs until condition true.

Test Command (Conditions)

  • test condition or [ condition ]
  • Enhanced: [[ condition ]] → regex, advanced comparisons.
  • Arithmetic: (( expression ))

File Tests

  • -e → Exists
  • -d → Directory
  • -s → Not empty
  • -x → Executable

String Tests

  • = → Equal
  • != → Not equal
  • -z → Empty string

Numeric Tests

  • -eq → Equal
  • -gt → Greater than
  • -lt → Less than

File Timestamp Tests

  • -nt → Newer than
  • -ot → Older than

Functions

function_name() {
    commands
}

Example:

hello() {
    echo "Welcome"
}

Rule: Function must be defined before calling. Otherwise, Bash may execute a program with the same name.

Running a Shell Script – Steps

  • Write the script.
  • Save the file.
  • Give execute permission: chmod +x script.sh
  • Run: ./script.sh

Quick Revision

  • Unix Philosophy → Do one thing well, text streams, stdin/stdout, pipes, minimal output.
  • Script Basics → Shebang, PATH, login vs non-login shell.
  • Running Scripts → source (same shell), ./script.sh (child shell).
  • Output → echo (simple), printf (formatted).
  • Command Substitution → $(command) preferred.
  • Special Variables → $0, $#, $1…, ${11}, "$@".
  • Flow Control → if, case, for, while, until.
  • Tests → [ ], [[ ]], (( )), file/string/numeric/timestamp tests.
  • Functions → Must be defined before calling.
  • Execution Steps → Write → Save → chmod → Run.
Memory Trick: "Shebang → PATH → Source/Execute → Variables → Conditions → Loops → Functions"

Lecture 3: Bash Scripts - Part 01

Introduction

  • Shell scripting automates repetitive tasks in Linux, making work faster and consistent.
  • Scripts usually use the .sh extension (e.g., backup.sh, install.sh, hello.sh).

Note: .sh is a convention, not a strict requirement.

Creating a Script with vi

  • Command: vi script.sh
  • Enter Insert Mode → i
  • Save & Exit → Esc → :wq

Shebang (#!)

  • First line: #!/bin/bash
  • Purpose: Ensures Bash interpreter runs the script, even if user's shell differs.

Comments

Begin with #

# This script creates a backup
echo "Backup Started"

Benefits: Explain code, improve readability, teamwork, easier updates.

File Permissions & Execution

  • New files are not executable → "Permission denied" error.
  • Grant permission: chmod 755 script.sh

Meaning of 755

UserPermissionValue
OwnerRead + Write + Execute7
GroupRead + Execute5
OthersRead + Execute5

Running a Script

  • Relative path: ./script.sh
  • Absolute path: /home/user/script.sh
  • Reason for ./: Current directory not in PATH for security.

Sourcing vs Direct Execution

FeatureSourcingDirect Execution
Command. script.sh / source script.sh./script.sh
PIDSame as parent shellNew child PID
Child ProcessNoYes
Variable PersistenceYesNo

Sourcing

  • Syntax: source script.sh or . script.sh
  • Runs in current shell, same PID, variables persist.
  • Useful for environment setup, SDK configuration.

Direct Execution

  • Syntax: ./script.sh
  • Creates child shell, new PID, variables disappear after exit.
  • Preferred for normal scripts.

$$ Variable

  • Stores current PID.
  • Example: echo $$

Variable Persistence Example

  • Script: export myvar="IITM"
  • Direct execution → variable disappears after script ends.
  • Sourcing → variable persists in current shell.

Positional Parameters

  • $0 → Script name/path.
  • $1, $2, $3… → Arguments.
  • $# → Number of arguments.

Examples

  • ./script.sh → $0 = ./script.sh
  • ./sum.sh 10 20 → $1 = 10, $2 = 20, $# = 2

Spaces & Quotes

  • ./script one two → $1 = one, $2 = two
  • ./script "one two" → $1 = "one two"

Conditional Statements

Basic if

if [ condition ]; then
    commands
fi

test Command

  • [ ] is shorthand for test.
  • Example: if [ -f file.txt ]

Comparison Operator

  • -ge → Greater than or equal to.
  • Example: if [ $# -ge 2 ]

Nested if

if [ $# -ge 2 ]; then
    if [ "$1" = "$2" ]; then
        echo "Arguments Match"
    fi
else
    echo "Please pass 2 or more arguments."
fi

Loops & Expansion

For Loop

for i in list
do
    commands
done

Brace Expansion

  • {a..d} → a b c d
  • {1..5} → 1 2 3 4 5
  • {a..d}{1..9} → 36 combinations

Command Substitution

  • Modern: $(command)
  • Old: `command` (not recommended).
for i in $(ls)
do
    echo $i
done

Practical System Scripts

Identify system scripts:

file /bin/* | grep "shell script"

.bashrc File

  • Location: ~/.bashrc
  • Loaded automatically for interactive non-login shells.
  • Common uses: aliases, environment variables, functions, customization.

Alias Example: alias ll="ls -l" → ll acts as ls -l

Safe Practice

  • Do not modify system files directly.
  • Copy and experiment separately.

Quick Revision

  • Script Creation → vi script.sh, #!/bin/bash, comments with #
  • Permissions → chmod 755 script.sh (Owner rwx, Group r-x, Others r-x)
  • Running Scripts → ./script.sh (relative), /home/user/script.sh (absolute)
  • Sourcing vs Execution → source (same shell, variables persist), ./ (child shell, variables vanish)
  • Positional Parameters → $0 (script name), $1…$n (arguments), $# (argument count)
  • Conditionals → if…fi, [ ] = test, -ge operator, nested if for safe checks
  • Loops & Expansion → for, {1..5}, {a..d}{1..9}, command substitution $(command)
  • System Scripts → file /bin/* | grep "shell script"
  • .bashrc → aliases, variables, functions, customization
Memory Trick: "Create → Shebang → chmod → Run → Source/Execute → Arguments → if → for → .bashrc"
