Lecture 1: Combining Commands and Files

Combining Multiple Commands

  • Semicolon (;) — runs commands sequentially, regardless of success or failure.
pwd ; date

Both commands execute independently.

  • Logical AND (&&) — executes the second command only if the first succeeds.
mkdir test && cd test
  • Logical OR (||) — executes the second command only if the first fails.
cd project || echo "Directory not found"

Execution in Subshells

  • Commands inside parentheses ( ) run in a subshell.
var=10
(var=20)
echo $var  # Output: 10
  • BASH_SUBSHELL variable shows nesting level:
echo $BASH_SUBSHELL
  • 0 → Main shell
  • 1+ → Subshell depth
  • Limitation: too many subshells increase system overhead.

File Descriptors

Linux uses three standard streams:

DescriptorNameNumberPurpose
stdinStandard Input0Input from keyboard
stdoutStandard Output1Normal command output
stderrStandard Error2Error messages

Output Redirection

Overwrite >

ls > files.txt
  • Creates file if missing.
  • Overwrites existing content.
  • Redirects only stdout.

Append >>

date >> log.txt
  • Adds new output at the end.
  • Preserves old content.
  • Safer than >.

Practical Applications & Limitations

Creating Files with cat

cat > notes.txt

Type content, press Ctrl + D to save.

Permissions

touch /usr/test.txt

May fail for normal users (system directories protected).

Handling Large Output

hwinfo > hardware.txt
less hardware.txt

Lecture 2: Redirections

Standard Error Redirection (2>)

  • Redirects stderr to a file.
command 2> error.txt

Rules: no space between 2 and >; only error messages are redirected; normal output still appears on screen.

ls /wrongpath 2> errors.txt

Error saved in errors.txt.

Uses: clean output (hide errors); debugging (store errors for troubleshooting).

Warning: existing file → overwritten. Missing file → created.

Combined Redirection (> and 2>)

Redirect stdout and stderr separately:

ls $HOME /blah > output.txt 2> error.txt
StreamDestination
stdoutoutput.txt
stderrerror.txt

Practical use:

ls -R /etc > files.txt 2> permission_errors.txt

Standard Input Redirection (<)

Sends file content as input:

command < file
  • cat < error.txt → displays file.
  • wc < error.txt → counts words, lines, characters.

Redirecting Error to Output (2>&1)

Problem:

command > file1 2> file1

Both streams conflict.

Solution:

command > file1 2>&1
  • > → stdout → file1
  • 2>&1 → stderr → same destination as stdout
ls $HOME /blah > all_output.txt 2>&1

Command Piping (|)

Sends output of one command as input to another:

command1 | command2
  • ls /usr/bin | wc -l → counts files.
  • ls /usr/bin | less → scroll interactively.

/dev/null — The Black Hole

Special file discards everything written.

ls -R /etc > output.txt 2> /dev/null
  • Output → output.txt
  • Errors → ignored

The tee Command

Splits output into screen + files.

command | tee file1
ls $HOME | tee file1 file2

Uses: logging while viewing live; multiple copies simultaneously.

Complex Chaining of Operators

Combine pipes, redirections, and tee:

ls $HOME /blah 2> /dev/null | tee file1 file2 | wc -l

Flow:

  1. 2> /dev/null → ignore errors.
  2. tee file1 file2 → save + display.
  3. wc -l → count lines.

Lecture 3: Software Management — Part 01

Introduction to Software Management

Earlier Linux installations required:

  • Manual source code download.
  • Compilation of programs.
  • Placement of binaries/libraries in correct locations.
  • Manual dependency resolution.

Modern package managers automate these tasks.

Why Use a Package Manager?

  • Convenience: manage thousands of packages easily.
  • Network installation: install/update directly from the internet.
  • Querying packages: search, list files, identify executables.
  • Dependency management: handle libraries, versions, upgrades.
  • Software authenticity: verify trusted sources.
  • Source code handling: manage source packages (e.g., kernel modules).

Major Linux Package Types

RPM (Red Hat Package Manager)

  • Original: Red Hat Linux.
  • Popular distros: CentOS, Fedora, Oracle Linux, SUSE, OpenSUSE.
  • Common usage: server environments.

DEB (Debian Package)

  • Original: Debian Linux.
  • Popular distros: Ubuntu, Linux Mint, Tails.
  • Common usage: desktop systems.

System Identification & Architecture

  • lsb_release -a → distribution, version, codename (e.g., Ubuntu 20.04 → codename: focal).
  • uname -a → kernel version, architecture.

Using apt-cache

Search packages:

apt-cache search nmap

List package names:

apt-cache pkgnames

Filter example:

apt-cache pkgnames nm

Show package details:

apt-cache show nmap

Debian Package Naming Convention

Format:

Name_Version-Revision_Architecture.deb

Example:

nmap_7.80+dfsg1-2build1_amd64.deb
  • nmap → package name
  • 7.80+dfsg1 → version
  • 2build1 → revision
  • amd64 → architecture

Lecture 4: Software Management — Part 02

User Privileges & Administrator Access

Sudo (Superuser Do)

Allows authorized users to execute commands as root.

sudo apt-get install nmap

Sudoers File

Location: /etc/sudoers — contains list of users with administrator privileges.

Authentication Logs

Location: /var/log/auth.log — tracks successful/failed attempts, unauthorized access. Purpose: monitor suspicious activity.

Package Repositories & Configuration

  • Main sources file: /etc/apt/sources.list — contains repository URLs and download locations.
  • Mirrors: faster downloads via regional servers (e.g., in.archive.ubuntu.com — India mirror).
  • Third-party repositories: location /etc/apt/sources.list.d/ (examples: Google Chrome, Zoom) — purpose: enable automatic updates via APT.

Using APT (Advanced Package Tool)

Update Package Information

sudo apt-get update

Synchronizes package index, checks for updates.

Upgrade Packages

sudo apt-get upgrade

Installs latest versions.

Install Packages

sudo apt-get install package_name

Remove Packages

sudo apt-get remove package_name

Reinstall Packages

sudo apt-get reinstall package_name

Remove Unused Dependencies

sudo apt-get autoremove

Clean Repository Cache

sudo apt-get clean

Purge Package (remove + config files)

sudo apt-get purge package_name

Using DPKG (Debian Package)

Difference:

APTDPKG
Downloads packagesWorks with local .deb files
Handles dependenciesDoes not auto-manage dependencies

Package information directory: /var/lib/dpkg — stores status, architecture, checksums.

Common Commands

List installed packages:

dpkg -l python

List package files:

dpkg -L package

Show package info:

dpkg -s package

Find package owner:

dpkg -S /usr/bin/perl

Install local .deb:

dpkg -i chrome.deb

Querying & Filtering Packages

dpkg-query: advanced searches.

dpkg-query -f='${Package}\n'

Using pipes:

  • Alphabetical sort: dpkg -l | sort
  • Page view: dpkg -l | less
  • Search category: dpkg -l | grep shell

Best Practices for System Stability

  • Avoid manual .deb installs → risk of conflicts/security issues.
  • Prefer APT → handles dependencies, checks compatibility.
  • Update regularly:
sudo apt-get update
sudo apt-get upgrade
  • Alternatives if conflicts occur: Snap, Docker.

Lecture 5: Linux Process Management

Introduction to Processes & sleep Command

  • A process is a running program in Linux.
  • sleep command: pauses execution for specified seconds.
sleep 10

Foreground execution: terminal locked until completion. Example: sleep 10 → prompt unavailable for 10 seconds.

Running Processes in the Background

  • coproc: creates asynchronous coprocess.
coproc sleep 20
  • & (ampersand): sends command to background.
sleep 30 &

Prompt remains available while process runs.

Monitoring Processes

  • ps: shows active processes.
ps
  • ps --forest: displays process tree (parent/child hierarchy).
  • jobs: lists active jobs in current shell.
  • top: real-time system monitor (CPU/memory usage, resource-heavy processes).

Job Control & Interruptions

  • fg: bring background/suspended job to foreground.
  • Ctrl + C: terminate foreground process immediately.
  • Ctrl + Z: suspend foreground process (kept in memory, can resume with fg).
  • kill PID: terminate process by ID.
kill 1234
  • kill -9 PID: force kill.
kill -9 1234

Shell Environment & Features

  • $-: shows shell flags.
echo $-
  • i → interactive shell
  • H → history expansion
  • B → brace expansion
  • $$: shows current shell PID.
echo $$
  • Command history: !25 → runs command number 25.

Expansion Features

Brace expansion:

echo {a..z}

Wildcard expansion:

ls *

Executing Multiple Commands

Sequential execution (;):

date ; pwd ; whoami

Commands run left to right, independent of success/failure.

Exit Codes & Return Status

  • Every command returns an exit code (0–255).
  • Check with:
echo $?

Common Exit Codes

Exit CodeMeaning
0Success
1General error / permission issue
2File/path not found
126Command found but not executable
127Command not found
130Stopped using Ctrl+C
137Killed using kill -9
  • Custom codes: values >255 → modulo 256. Example: 300 % 256 = 44.
  • Importance: used in conditional execution, scripting, automation.
command1 && command2
