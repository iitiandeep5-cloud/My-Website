Lecture 1: The Benefits of Indirection

Core Concept

  • Abstraction → What a data structure does
  • Implementation → How it does it
  • Program to an interface, not to an implementation.
  • Abstract Data Type (ADT) → Defines operations, not internal details.

Example: Queue ADT

  • Follows FIFO (First In First Out).
  • Public operations:
    • add() → Insert at rear
    • remove() → Remove from front
    • size() → Return number of elements

Queue Implementations

A. Circular Array Queue

  • Uses fixed-size array, wraps around with modulo.
  • Size = (tail - head) % capacity
  • Advantages: Fast, memory efficient, contiguous memory, predictable usage
  • Disadvantages: Fixed size, queue can become full, overflow possible

B. Linked List Queue

  • Each element stored in a node (data + next reference).
  • Advantages: Dynamic size, no fixed capacity, grows as needed, no overflow until heap full
  • Disadvantages: Extra memory for pointers, node creation overhead, slightly slower

Comparison Table

FeatureCircular ArrayLinked List
StorageArrayNodes
SizeFixedDynamic
PointersHead & Tail IndexHead & Tail Pointer
SpeedFastFlexible
MemoryLess overheadMore overhead
OverflowPossibleGrows automatically

Problem of Using Concrete Classes

CircularArrayQueue q = new CircularArrayQueue();
  • Creates Tight Coupling → dependent on one class.
  • Problems: Difficult maintenance, difficult upgrades, error-prone, creates technical debt.

Java Interfaces

  • Interface = capability, not implementation.
  • Example hierarchy:
Queue (Interface) / \ CircularArrayQueue LinkedListQueue

Correct way:

Queue q = new CircularArrayQueue();

Later:

Queue q = new LinkedListQueue();
  • Only one line changes → Loose Coupling.
  • Runtime decides actual method → Dynamic Dispatch.

Indirection

  • Definition: Intermediate layer between program and implementation.

Famous quote (Butler Lampson):

"All problems in computer science can be solved by adding another level of indirection."
  • Real-life analogy: Office cars (pool, taxi service, reimbursement).

Key Definitions

  • ADT → Defines operations, not implementation.
  • Interface → Contract of methods, no code.
  • Implementation → Actual code.
  • Tight Coupling → Code depends on specific class.
  • Loose Coupling → Code depends on interface.
  • Dynamic Dispatch → Runtime decides actual method.
  • Indirection → Add intermediate layer for flexibility.
  • Technical Debt → Extra work caused by poor design.

Quick Revision

  • ADT = What, Implementation = How
  • Queue → add(), remove(), size()
  • Implementations → Circular Array (fast, fixed) vs Linked List (dynamic, overhead)
  • Concrete class → Tight Coupling
  • Interface → Loose Coupling
  • Runtime → Dynamic Dispatch
  • Indirection → Interface layer adds flexibility
  • Butler Lampson → Indirection solves problems

Lecture 2: Collection

The Problem: Why Do We Need Indirection?

  • Early commitment to a specific data structure (e.g., ArrayList, Vector, Stack) creates Tight Coupling.
ArrayList<String> list = new ArrayList<>();

Entire program depends on ArrayList. Switching to LinkedList requires changes everywhere.

Problems of Tight Coupling

  • Many files need modification
  • Different data structures have different methods
  • High maintenance cost
  • Difficult to improve performance later
  • Less scalable

Solution → Indirection

  • Program to an interface, not a class.
List<String> list = new ArrayList<>();

Later:

List<String> list = new LinkedList<>();
  • Only one line changes, rest of the program remains intact.

Java Before Collections Framework

  • Classes like Vector, Stack, Hashtable were siloed, each with unique methods.
  • Switching between them was difficult.

Modern Java

  • Introduced hierarchy of interfaces.
  • Benefits: Easy switching, code reuse, loose coupling, better maintenance.

Collection Interface

  • Root interface for storing groups of objects.
  • Examples: ArrayList, LinkedList, HashSet, TreeSet, Queue.

Collection Stores: Group of values (e.g., 10, 20, 30, 40).

Collection Does Not Store: Key–Value pairs → handled by Map (HashMap, TreeMap).

Collection vs Map

FeatureCollectionMap
StoresGroup of valuesKey–Value pairs
AccessIterationKey lookup
ExamplesList, Set, QueueHashMap, TreeMap

Generics in Collections

  • Syntax: Collection<E> → E = element type.
Collection<String> names;
names.add("Rahul");
names.add("Priya");
  • Benefits: Type safety, prevents wrong data, compile-time errors, no unnecessary casting.

Iterator

  • Traverses collections uniformly.
  • Methods:
    • hasNext() → checks if another element exists
    • next() → returns next element, moves forward
    • remove() → deletes last element returned by next()

Iterator Flow

Start → hasNext() → next() → Current Element → remove() (optional) → repeat

Important Rule: remove() only works after next().

For-Each Loop

for (String name : names) { ... }
  • Internally uses an Iterator.
  • Limitation: Cannot call remove() inside for-each.

Common Collection Methods

MethodPurpose
add()Insert one element
addAll()Insert another collection (Union)
contains()Check one element
containsAll()Check all elements (Superset)
remove()Remove one object
removeAll()Remove another collection (Set Difference)
iterator()Traverse collection
size()Number of elements

Note: contains() depends on proper equals() implementation.

Problem While Implementing Collection

  • Custom class implementing Collection must define all methods → tedious.

Solution → AbstractCollection

  • Provides ready-made implementations for many methods (contains(), addAll(), removeAll(), etc.).
  • Still abstract: iterator() and size() → must be implemented by each collection.

Reason: Traversal and size depend on internal storage (array, nodes, hashing).

Java Collection Hierarchy

Collection (Interface) │ AbstractCollection (Abstract Class) │ ┌────┼─────┐ │ │ │ ArrayList LinkedList HashSet

Advantages of Collection Framework

  • Loose coupling
  • Reusable code
  • Type safety (Generics)
  • Standard API
  • Easy traversal (Iterator)
  • Easy switching of implementations
  • Better scalability
  • Better maintainability

Key Definitions

  • Collection → Root interface for groups of objects.
  • Map → Stores key–value pairs.
  • Generic (E) → Element type in a collection.
  • Iterator → Object for traversing collections.
  • For-Each Loop → Simplified syntax using Iterator internally.
  • AbstractCollection → Abstract class with common implementations.
  • Indirection → Interface between program and implementation.

Quick Revision

  • Directly using ArrayList or LinkedList → Tight Coupling
  • Use List or Collection interface → Loose Coupling
  • Collection = group of values; Map = key–value pairs
  • Generics ensure type safety
  • Iterator → hasNext(), next(), remove()
  • For-Each loop uses Iterator internally, cannot remove elements
  • contains() depends on equals()
  • addAll() = Union, removeAll() = Set Difference, containsAll() = Superset check
  • AbstractCollection reduces work, but iterator() and size() must be implemented
  • Hierarchy: Collection → AbstractCollection → Concrete Classes

Lecture 3: Concrete Collections

Introduction

  • Interface → Defines what to do (abstract, cannot store data).
  • Concrete Class → Defines how to do it (actual implementation, stores data).
  • Importance: Different applications need different features (fast search, fast insertion, ordered data, unique data, low memory usage).
  • Java provides multiple implementations to suit different needs.

Collection Framework Stores: Groups of values → List, Set, Queue.

Collection Framework Does Not Store: Key–Value pairs → handled by Map (HashMap, TreeMap).

List Interface

  • Stores elements in ordered sequence with indexes.

Access Methods

  • Sequential Traversal → via Iterator.
  • Random Access → direct index access (list.get(i)).

Extra Methods

  • add(index, element) → insert at position.
  • remove(index) → remove element at position.
  • get(index) → return element at index.
  • set(index, value) → replace element.

ListIterator

  • More powerful than Iterator.
  • Methods: next(), previous(), hasPrevious(), add().

ArrayList vs LinkedList

  • Both implement List, but differ internally.

ArrayList

  • Uses dynamic array.
  • Advantages: Fast random access, efficient indexing, less memory, better cache performance.
  • Time complexity: Random access → O(1).

LinkedList

  • Uses nodes + references.
  • Advantages: Fast insertion/deletion, good for frequent modifications.
  • Weakness: Random access → O(n).

Exam Concept:

  • Loop with get(i) on LinkedList → O(n²).
  • On ArrayList → O(n).

RandomAccess Interface

  • Marker interface (no methods).
  • Indicates fast random access support.
  • Example: ArrayList implements it, LinkedList does not.

Set Interface

  • Stores unique elements only.
  • Main purpose: Membership checking.

HashSet

  • Uses hashing (hashCode() → index).
  • Very fast search, insert, delete (average O(1)).
  • Limitation: Unpredictable iteration order.

TreeSet

  • Stores elements in sorted order using search trees.
  • Requirement: Elements must be comparable.
  • Time complexity: Insert/Delete/Search → O(log n).

StorageHashingSearch Tree

Queue Interface

  • Follows FIFO (First In First Out).

Queue Operations

OperationHard MethodGentle Method
Insertadd()offer()
Removeremove()poll()
View Frontelement()peek()
  • Hard methods throw exceptions if operation fails.
  • Gentle methods return special values (false or null).

Deque (Double Ended Queue)

  • Allows insertion/deletion at both ends.
  • Methods:
    • Front → offerFirst(), pollFirst(), peekFirst()
    • Rear → offerLast(), pollLast(), peekLast()

PriorityQueue

  • Removes highest priority element first (not FIFO).
  • Example: Hospital emergency queue, airport premium queue.

Java Collection Hierarchy

Collection (Interface) │ ┌────┼─────┐ │ │ │ List Set Queue │ │ │ AbstractList AbstractSet AbstractQueue │ AbstractSequentialList │ LinkedList (ArrayList also extends AbstractList.)

Key Terms

  • ArrayList → Fast reading, slow middle insert/delete.
  • LinkedList → Fast insert/delete, slow random access.
  • HashSet → Fast membership checking, no ordering.
  • TreeSet → Sorted data, slower operations.
  • Queue → Arrival-based processing.
  • PriorityQueue → Priority-based processing.

Some Definitions

  • List → Ordered collection, allows duplicates, supports index access.
  • ArrayList → Dynamic array, fast random access.
  • LinkedList → Node-based, efficient insert/delete.
  • RandomAccess → Marker interface for fast indexed access.
  • Set → Stores unique elements.
  • HashSet → Hash-based, fast search, unordered.
  • TreeSet → Tree-based, sorted order.
  • Queue → FIFO collection.
  • Deque → Double-ended queue.
  • PriorityQueue → Removes highest priority element first.
  • AbstractCollection → Provides default implementations.
  • AbstractList → Common list functionality.
  • AbstractSequentialList → For sequential-access lists like LinkedList.

Quick Revision

  • Concrete Collections = actual implementations.
  • Collection = groups of values; Map = key–value pairs.
  • List → ordered, duplicates allowed, indexed access.
  • ArrayList → O(1) random access.
  • LinkedList → O(n) random access, fast insert/delete.
  • RandomAccess → marker interface for fast access.
  • Set → unique elements.
  • HashSet → unordered, O(1).
  • TreeSet → sorted, O(log n).
  • Queue → FIFO.
  • Deque → operations at both ends.
  • PriorityQueue → priority-based removal.
  • AbstractCollection → AbstractList → AbstractSequentialList reduce coding effort.

Lecture 4: Maps

Introduction to Map

  • Map stores data as Key → Value pairs.
Rahul → 95 Priya → 88 Aman → 91
  • Key = unique identifier, Value = associated data.

Map vs Collection

FeatureCollectionMap
StoresGroup of valuesKey–Value pairs
AccessIndex/IterationKeys
EntrySingle valueTwo values (Key & Value)
Parent InterfaceCollectionMap
DuplicatesDepends on implementationKeys unique, values can repeat

Generics

  • Collection → Collection<E> (one type).
  • Map → Map<K,V> (two types).
Map<String,Integer> score;

Basic Map Methods

  • put(key,value) → Adds new pair, replaces old value if key exists. Returns old value.
  • get(key) → Returns value for key.
  • containsKey(key) → Checks if key exists.

Type Safety Paradox

  • put() strictly checks types.
  • get(Object key) and containsKey(Object key) accept Object.
  • Reason: Internally uses equals(Object).

Advanced Update Methods

  • getOrDefault(key,defaultValue) → Returns default if key absent.
  • putIfAbsent(key,value) → Adds only if key not present.
  • merge(key,newValue,function) → Atomic update (initialize or update in one step).
MethodPurpose
getOrDefault()Return default if key absent
putIfAbsent()Initialize if absent
merge()Initialize or update atomically

Map Views

  • Map itself is not a Collection, but provides views:
    • keySet() → Set<K> (keys are unique).
    • values() → Collection<V> (values may repeat).
    • entrySet() → Set<Map.Entry<K,V>> (each entry = key + value).

Iterating a Map

  • Method 1: Using keySet() → requires extra lookup.
  • Method 2 (Best): Using entrySet() → direct access to key and value.

HashMap vs TreeMap

  • HashMap → Uses hash table.
    • Performance: Insert/Search/Delete → O(1) average.
    • Limitation: Unordered iteration.
  • TreeMap → Uses balanced search tree (Red-Black Tree).
    • Keys remain sorted.
    • Performance: Insert/Delete/Search → O(log n).
FeatureHashMapTreeMap
StorageHash TableBalanced Tree
OrderUnorderedSorted
SpeedFasterSlower
ComplexityO(1)O(log n)

LinkedHashMap

  • Extends HashMap, combines hash table + doubly linked list.
  • Maintains order:
    • Insertion Order → elements remain in order inserted.
    • Access Order → recently accessed elements move to end.

LRU (Least Recently Used)

  • Cache replacement policy: removes entry not accessed for longest time.
  • Implemented using LinkedHashMap + removeEldestEntry().

LinkedHashSet: Similar to LinkedHashMap, but for unique elements with insertion order.

Java Map Hierarchy

Important Exam Definitions

  • Map → Interface storing Key–Value pairs.
  • Key → Unique identifier.
  • Value → Data associated with key.
  • HashMap → Fast lookup, unordered.
  • TreeMap → Sorted keys, slower operations.
  • LinkedHashMap → Maintains insertion/access order.
  • getOrDefault() → Returns default if key absent.
  • putIfAbsent() → Adds only if key not present.
  • merge() → Atomic update.
  • keySet() → Set of keys.
  • values() → Collection of values.
  • entrySet() → Set of key–value entries.
  • LRU → Removes least recently used entry.

Quick Revision

  • Map ≠ Collection.
  • Map stores Key–Value pairs.
  • Syntax → Map<K,V>.
  • Keys unique, values can repeat.
  • put() replaces old value, returns old.
  • getOrDefault() prevents null.
  • putIfAbsent() initializes if absent.
  • merge() atomic update.
  • keySet() → keys, values() → values, entrySet() → key+value.
  • HashMap → O(1), unordered.
  • TreeMap → O(log n), sorted.
  • LinkedHashMap → O(1), maintains order.
  • LRU cache → implemented with LinkedHashMap.
