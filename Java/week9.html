Lecture 1: Optional Types

Problem Optional Solves

  • Null handling was error-prone.
  • Using null caused NullPointerException (NPE) if checks were missed.
  • Optional makes absence explicit, shifting error handling from runtime to compile-time.

Why Streams Return Optional

  • Operations like max() or min() may not yield results.
  • Example: Empty list → no maximum.
  • Returning 0 would be misleading.
  • Instead, Java returns Optional.empty() to represent absence safely.

Traditional vs Optional

Traditional (null)Optional
Returns nullReturns Optional.empty()
Manual null checksBuilt-in handling methods
Runtime NPE riskSafer functional handling
Hidden absenceExplicit absence

Optional as a Box

  • Present state → Optional.of(10)
  • Empty state → Optional.empty()
  • Difference:
    • null → no object exists
    • Optional.empty() → object exists, but no value

Optional Types for Primitives

  • Specialized versions: OptionalInt, OptionalLong, OptionalDouble
  • Example: DoubleStream.max() → returns OptionalDouble
  • Avoids boxing/unboxing → better performance.

Creating Optional Objects

  • Optional.empty() → empty box
  • Optional.of(value) → non-null value only
  • Optional.ofNullable(value) → safest, handles both null & non-null

Extracting Values

  • orElse() → default replacement
  • orElseGet() → lazy default computation
  • orElseThrow() → throws exception if empty

Conditional Execution

  • ifPresent() → run code only if value exists
  • ifPresentOrElse() → handle both present & absent cases

Producer-Side Design

  • Methods returning Optional create type-level contracts.
  • Example: Safe inverse function returns Optional.empty() when undefined.

Transforming Optional Values

  • map() → transforms value if present
  • flatMap() → flattens nested Optional, enables chaining

Cascading Pipelines

Optional<Double> result =
    safeInverse(x)
        .flatMap(MyClass::safeSquareRoot)
        .map(v -> v * 2);
  • Failures propagate automatically.
  • No manual null checks needed.

Stream.ofNullable()

  • Bridges legacy APIs returning null.
  • Converts null → empty stream.
  • Useful for modern stream pipelines.

map vs flatMap

map()flatMap()
Returns OptionalReturns Optional
Function returns normal valueFunction returns Optional
Can create nested OptionalFlattens nested Optional
Simple transformationChaining Optional-returning methods

Best Practices

  • Use Optional for return types, not fields/parameters.
  • Prefer Optional.ofNullable() for uncertain inputs.
  • Avoid get() → use safer methods (orElse, map, flatMap).
  • Use flatMap() when chaining Optional-returning methods.

Conclusion

  • Optional = explicit presence/absence contract.
  • Eliminates unsafe null handling.
  • Improves safety, readability, modularity, functional programming, and API design.
Exam key idea: Optional replaces null with a safe, functional, and composable abstraction.

Lecture 2: Collecting Results From Streams

Lifecycle Overview

  • Collection → stores data permanently.
  • Stream → processes data temporarily.
Typical flow: Collection → Stream → Intermediate operations → Terminal operation → Result

Example

List<String> names = List.of("A", "B", "C");
List<String> result =
    names.stream()
         .filter(s -> s.length() == 1)
         .collect(Collectors.toList());

Terminal operation converts temporary stream back into a stable structure.

Immediate Access Methods

  • iterator() → manual traversal, legacy style.
  • forEach() → modern, cleaner syntax, functional style.

Converting Stream to Array

  • Default toArray() → returns Object[], type info lost.
  • Typed toArray() → String[] arr = stream.toArray(String[]::new); → Always prefer typed version.

collect() Terminal Operation

  • Opposite of stream().
  • Converts stream into collection or other result.
  • Syntax: stream.collect(collector);

Common Collectors

  • toList() → List
  • toSet() → Set (removes duplicates)
  • toCollection() → specific collection type (e.g., TreeSet)

Summary Statistics

  • summarizingInt() → computes count, sum, min, max, average in one pass.
IntSummaryStatistics stats =
    names.stream()
         .collect(Collectors.summarizingInt(String::length));

Methods in IntSummaryStatistics

MethodMeaning
getCount()number of elements
getSum()total sum
getMin()smallest value
getMax()largest value
getAverage()average value

Similar: summarizingLong(), summarizingDouble()

Empty Stream Behavior

MethodReturns
getCount()0
getSum()0
getAverage()0.0
getMax()Integer.MIN_VALUE
getMin()Integer.MAX_VALUE

Collecting into a Map

Basic toMap()

Map<Integer, String> map =
    people.stream()
          .collect(Collectors.toMap(
              Person::getId,
              Person::getName
          ));

Identity Mapping

Map<Integer, Person> map =
    people.stream()
          .collect(Collectors.toMap(
              Person::getId,
              Function.identity()
          ));

Duplicate Key Problem

  • Throws IllegalStateException if duplicate keys exist.
  • Solve with merge function: (oldValue, newValue) -> oldValue

groupingBy()

  • Groups elements into multiple buckets.
Map<String, List<Person>> grouped =
    people.stream()
          .collect(Collectors.groupingBy(Person::getName));

partitioningBy()

  • Special case of grouping → exactly two groups.
  • Uses Predicate.
Map<Boolean, List<Person>> partition =
    people.stream()
          .collect(Collectors.partitioningBy(
              p -> p.getName().startsWith("A")
          ));

groupingBy vs partitioningBy

groupingBy()partitioningBy()
Many groupsExactly two groups
Classifier functionPredicate
Keys can be any typeKeys are Boolean
Map<K, List<V>>Map<Boolean, List<V>>

Revision Table

Conclusion

  • Flow: Collection → Stream → Processing → collect()
  • Key collectors: toList(), toSet(), toCollection(), toMap(), groupingBy(), partitioningBy(), summarizingInt()
Core concept: collect() transforms the temporary stream back into a stable result structure, while collectors define how elements are accumulated, grouped, mapped, partitioned, or summarized.

Lecture 3: Input/Output Streams

What is Java I/O?

  • I/O = mechanism for communication between a Java program and the outside world.
  • Examples: files, keyboard input, console output, network connections, memory.
  • Without I/O, a program remains isolated.

What is a Stream?

  • A stream = continuous flow of data.
  • InputStream → source → program
  • OutputStream → program → destination

Important Distinction

Java I/O StreamsJava Stream API
java.iojava.util.stream
Moves dataProcesses collections
Reads/writes bytesFunctional programming

Why Interpretation is Needed

  • External data stored as bytes (0s and 1s).
  • Same bytes can represent text, integers, floats, images, executables.
  • Java provides layers to interpret raw bytes into meaningful types.

Base Classes

  • InputStream → reads bytes
    • int read() → returns 0–255 (valid byte), -1 (EOF)
  • OutputStream → writes bytes
    • write(int b)
    • write(byte[] arr)

Blocking & Resource Management

  • Reading may block if data unavailable (e.g., slow network).
  • available() → checks how many bytes are ready.
  • Always close() streams to release resources.
  • flush() → forces buffered data to be written.

File Streams

  • FileInputStream → read from file
  • FileOutputStream → write to file
    • Default: overwrite
    • Append mode: new FileOutputStream("data.txt", true)

Scanner

  • High-level wrapper for reading text.
  • Example: Scanner sc = new Scanner(System.in);
MethodPurpose
next()next token
nextLine()entire line
nextInt()integer
hasNext()check input

PrintWriter

  • For formatted text output.
PrintWriter pw = new PrintWriter("output.txt");
pw.println("Hello");
pw.close();

Exception Handling

  • I/O can fail → FileNotFoundException, IOException.
  • Always use try-catch.

Binary I/O

  • Text is inefficient for numbers.
  • DataInputStream → read primitives (readInt(), readDouble(), readUTF())
  • DataOutputStream → write primitives (writeInt(), writeDouble(), writeUTF())

Decorator Design Pattern

  • Java I/O uses Decorator Pattern.
  • Example pipeline:
DataInputStream dis =
    new DataInputStream(
        new BufferedInputStream(
            new FileInputStream("data.bin")
        )
    );

Layers: File → Buffer → Interpreter.

Buffered Streams

  • BufferedInputStream → reads in chunks, improves performance.
  • PushbackInputStream → allows unread().
  • ZipInputStream → reads compressed ZIP data.

RandomAccessFile

  • Supports random access.
RandomAccessFile raf =
    new RandomAccessFile("data.bin", "rw");
raf.seek(1000);

Useful for databases, binary formats, large files.

Sequential vs Random Access

Sequential StreamsRandomAccessFile
Read from beginningJump anywhere
Forward onlyseek(position)
Continuous flowNon-linear access

Conclusion

  • Architecture: Source → Stream → Buffer → Interpreter → Program
  • Key concept: Decorator Pattern builds efficient pipelines.
Exam line: Java I/O streams move raw bytes between a program and external sources, while layered wrappers (buffering, parsing, binary interpretation, compression) provide modular, efficient, and flexible data processing.

Lecture 4: Serialization

Definition

  • Serialization → converting a Java object into a stream of bytes.
  • Deserialization → reconstructing the object from bytes.
Easy definition:
  • Serialization: object → bytes
  • Deserialization: bytes → object

Why Serialization is Needed

  • Without serialization → must manually write each field.
  • Tedious and error-prone.
  • Serialization automatically writes the entire object.

Main Use Cases

  • Program state persistence → save/restore game progress, settings, sessions.
  • Distributed applications → transmit objects between JVMs over a network.

Object Streams

  • ObjectOutputStream → write objects.
  • ObjectInputStream → read objects.

Writing

ObjectOutputStream oos =
    new ObjectOutputStream(new FileOutputStream("emp.dat"));
oos.writeObject(emp);
oos.close();

Reading

ObjectInputStream ois =
    new ObjectInputStream(new FileInputStream("emp.dat"));
Employee emp = (Employee) ois.readObject();
ois.close();

Serializable Interface

  • Class must implement Serializable.
  • Marker interface → no methods.
  • Without it → NotSerializableException.

Object Graph & Identity

  • Serialization preserves shared references.
  • Uses serial number mechanism:
    • First occurrence → full object written.
    • Later occurrences → reference reused.

Transient Fields

  • Exclude fields from serialization.
  • Example: transient Socket socket;
  • During deserialization → primitives → default values, objects → null.

Custom Serialization

  • Override writeObject() and readObject().
  • Use defaultWriteObject() and defaultReadObject() for normal fields.
  • Manually handle transient fields.

Serialization Process Summary

  • Normal fields → automatic.
  • Transient fields → ignored.
  • Custom handling → manual.

Risks of Serialization

  • Versioning problems → class changes break old data.
  • Encapsulation problem → exposes internal structure.
  • Security risk → deserializing untrusted data can be exploited.
Safe: local backups, trusted data.
Unsafe: network data, external files.

Important Methods

MethodPurpose
writeObject()serialize object
readObject()deserialize object
defaultWriteObject()serialize normal fields
defaultReadObject()restore normal fields

Conclusion

Flow: Object → ObjectOutputStream → Byte Stream → Storage/Network → ObjectInputStream → Reconstructed Object

Key concepts:

  • Serializable interface
  • Object identity preservation
  • Transient fields
  • Custom writeObject() and readObject()
  • Versioning & security risks
Exam line: Java serialization converts complete objects into byte streams while preserving identity and state. Deserialization reconstructs the object graph automatically, but requires Serializable permission and careful handling of transient fields, version compatibility, and untrusted input.
