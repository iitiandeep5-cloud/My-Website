Lecture 1: Application Design and Development / 1

Introduction to Application Design

Goals of application design:

  • Efficient (fast & low memory)
  • Secure (protect user data)
  • Scalable (handle more users)

Modern applications: data-intensive; connected to a database.

Diversity vs Unity of Applications

Diverse Sectors:

  • Finance → UPI, Net Banking
  • Travel → Booking apps
  • Communication → Video calling apps
  • Health → Telemedicine
  • Education → Learning platforms

Internal Systems (ERP): used inside organizations (schools, hospitals); works on intranet. Examples: Student Management System, Hospital ERP.

Deep Unity (Common Feature) All use RDBMS (MySQL, PostgreSQL, Oracle) and SQL for data operations.

Three-Tier Architecture

1. Frontend (Presentation Layer): user interacts here (UI). Examples: forms, buttons, login page.

MVC Pattern:

  • Model → Data + validation
  • View → UI (what user sees)
  • Controller → Connects Model & View

2. Business Logic Layer (Middle Layer): brain of application; handles authentication, business rules, workflows; converts DB data → Objects using ORM.

3. Backend (Data Access Layer - DAL): stores data in database; handles queries (SQL), storage & retrieval.

Example Flow User clicks "Buy" → Frontend sends request → Business logic checks payment & stock → Backend fetches data → Response shown to user.

Database Design Strategies

Centralized Database: simple, not scalable.

Distributed Database: faster & scalable, handles large systems. Example: data stored by region (India, US, Europe).

Evolution of Architecture

EraDescription
1970sMainframe (centralized)
1980sPCs + LAN
1990sInternet & Web
2000s+Mobile apps, cloud

Types of Tier Architectures

  • 1-Tier: Everything in one system, not scalable
  • 2-Tier (Client-Server): Client + Database server, limited scalability
  • 3-Tier (Most Important): Frontend + Logic + Database, clean separation, scalable
  • N-Tier: Multiple servers, used in big apps like Amazon, Google

Example: Web Mail Application

Presentation Layer: Login page, Inbox view, Compose mail

Business Logic: Authentication, Encryption/Decryption, Mail sending logic

Database Layer: Stores emails, contacts, user data

Sample Code (Simple 3-Tier Example)

Backend (Python Flask):

Python
from flask import Flask, jsonify

app = Flask(__name__)

@app.route('/data')
def get_data():
    return jsonify({"message": "Hello from backend"})

app.run()

Frontend (HTML + JS):

Html
<button onclick="loadData()">Click</button>

<script>
function loadData() {
  fetch('/data')
    .then(res => res.json())
    .then(data => alert(data.message));
}
</script>

Database Query (SQL):

Sql
SELECT * FROM users WHERE id = 1;
Final Summary — Revision
  • Applications = Frontend + Logic + Database
  • Most apps use 3-tier architecture
  • RDBMS + SQL are common
  • Key goals: Efficiency, Security, Scalability
  • Modern systems: Distributed databases, N-tier architecture

Lecture 2: Application Design and Development / 2

Three-Tier Architecture (Most Important)

Modern web apps are divided into 3 layers:

  1. Presentation Layer (Frontend) — what user sees (UI). Examples: Login page, Forms, Buttons.
  2. Business Logic Layer (Backend) — handles rules (login validation), processing data, calculations.
  3. Data Access Layer (Database) — stores data (users, products, etc.), uses SQL queries.
Basic Flow of Web Application User (Browser) → HTTP Request → Web Server → Process (Logic + DB) → Response (HTML/JSON) → User sees result

Web Fundamentals & Identification

World Wide Web (WWW): global system of interconnected web pages; based on hypertext (links).

HTML (HyperText Markup Language): used to create web pages; uses tags.

Common Tags:

  • <table> → Table
  • <tr> → Row
  • <th> → Header
  • <form> → User input
Html
<table>
  <tr>
    <th>Name</th>
  </tr>
</table>

<form>
  <input type="text" />
</form>

Resource Identification

URL (Uniform Resource Locator): address of a web page.

Example https://www.google.com/search?q=chatgpt
Protocol → https  |  Host → google.com  |  Path → /search
  • URI (Uniform Resource Identifier): general term for all identifiers
  • URN (Uniform Resource Name): name, not location (e.g., ISBN of a book)

Communication Protocols & State

HTTP (HyperText Transfer Protocol): communication between browser & server; stateless (connectionless) → each request is independent.

Cookies: small data stored in browser; used to remember user, track login.

Sessions: temporary connection between client & server; stores user data on server.

Timeout: session expires after inactivity; improves security & performance.

System Components

Web Browser: examples: Chrome, Edge; converts HTML → visual page (process called Rendering).

Web Server: receives HTTP requests; sends back response (HTML/JSON).

Scripting Technologies

What is Scripting? Lightweight code; interpreted (runs directly).

Client-Side Scripting (Browser):

  • Runs in browser
  • Example: JavaScript
  • Uses: Form validation, UI updates
  • Security: Cannot access local files
Html
<script>
function check() {
  let x = document.getElementById("num").value;
  if (isNaN(x)) {
    alert("Enter a number");
  }
}
</script>

Server-Side Scripting (Server):

  • Runs on server
  • Examples: Python (Flask/Django), PHP, JSP
  • Uses: Database operations, dynamic content generation
Python
from flask import Flask

app = Flask(__name__)

@app.route('/')
def home():
    return "Hello User"

app.run()

Servlets: Java-based server programs; handle multiple users using threads.

JSP (Java Server Pages): mix HTML + Java code; easier than Servlets.

Final Revision
  • Web apps follow 3-Tier Architecture
  • HTTP is stateless (uses cookies & sessions)
  • Key components: Browser + Server
  • Scripting — Client-side: JavaScript. Server-side: Python, PHP, JSP

Lecture 3: Application Design and Development / 3

1. Three-Tier Architecture Context

Three Layers Recap:

  • Presentation Layer — browser-based UI. Technologies: HTML, CSS, JavaScript
  • Middle Layer (Application Layer) — written in Python, Java, C++. Handles business logic, data processing
  • Data Layer — database (MySQL, PostgreSQL, etc.); uses SQL
Integration Challenge Problem: Programming languages use objects, databases use tables (relations).
Solution: need a bridge to execute SQL, get table results, and convert into usable program data.

Core Connectivity Workflow

Standard Steps (Same Everywhere):

  1. Establish Connection → Username & password
  2. Send SQL Query → SELECT / INSERT / UPDATE
  3. Database Processes Query → Returns rows (tuples)
  4. Fetch Data → Program reads rows one by one
  5. Close Connection → Free resources

Connectionist Approach (API-Based)

Idea: Use a library/driver as a bridge → Program ↔ Database

ODBC (Open Database Connectivity): works across different OS & databases; portable, standard API.

Python Example (pyodbc):

Python
import pyodbc

conn = pyodbc.connect(
    "DRIVER={SQL Server};SERVER=localhost;DATABASE=test;UID=user;PWD=pass"
)

cursor = conn.cursor()
cursor.execute("SELECT * FROM students")

row = cursor.fetchone()
while row:
    print(row)
    row = cursor.fetchone()

conn.close()
  • cursor → points to rows
  • fetchone() → gets one row

JDBC (Java Database Connectivity):

Java
Connection con = DriverManager.getConnection(
    "jdbc:mysql://localhost:3306/test", "user", "pass");

Statement stmt = con.createStatement();
ResultSet rs = stmt.executeQuery("SELECT * FROM students");

while(rs.next()) {
    System.out.println(rs.getInt("id"));
}

con.close();
  • ResultSet → stores query results
  • .next() → iterate rows

Bridge Drivers: Connect different systems (e.g., ODBC ↔ JDBC bridge)

Embedded SQL Approach

Idea: Write SQL inside program code.

Syntax Indicators:

  • EXEC SQL (C/C++)
  • #SQL (Java-like systems)

Host Variables: used to exchange data. Example: :int student_id;

Cursor Workflow:

  1. Declare cursor
  2. Open cursor
  3. Fetch rows
  4. Close cursor

Conceptual Example (C-style):

C
EXEC SQL DECLARE c CURSOR FOR
SELECT id FROM students;

EXEC SQL OPEN c;

while(1) {
    EXEC SQL FETCH c INTO :id;
    if(no_more_rows) break;
    printf("%d", id);
}

EXEC SQL CLOSE c;

Update using Cursor: modify current row → WHERE CURRENT OF c;

Key Programming Concepts

Cursors / Iterators: move through rows one-by-one; used in JDBC, Python, Embedded SQL.

Exception Handling: handles errors like wrong password, table not found.

Python
try:
    conn = pyodbc.connect("wrong_credentials")
except Exception as e:
    print("Error:", e)

Data Dictionary: stores metadata (info about tables)

Sql
SELECT * FROM information_schema.tables;

Used to check table existence, avoid errors before CREATE/DROP.

Final Quick Revision
  • 3-Tier = Frontend + Logic + Database
  • Problem = Object ↔ Table mismatch
  • Solution = API (ODBC, JDBC) or Embedded SQL
  • Workflow = Connect → Query → Fetch → Close
  • Cursor = row iterator; ResultSet = query output; Exception handling = error safety

Lecture 4: Application Design and Development / 4

Introduction to the Tech Stack

Choice of Tools:

  • Python → Popular language for development
  • PostgreSQL → Free, open-source database

Focus: lecture concentrates on frontend (GUI) and backend (data access); skips middle-tier business logic to emphasize connection between extremes.

Database Modules: Python has several PostgreSQL modules. Focus here: psycopg2.

Psycopg2 Module Concepts

Most popular PostgreSQL adapter for Python.

Key Features:

  • Stable & actively maintained
  • Supports Python 2.x & 3.x
  • Thread-safe → suitable for multi-threaded apps

Installation:

Bash
pip install psycopg2

Database Connection Workflow

Standard Workflow Steps:

  1. Create a Connection → connect() establishes link to DB server
  2. Create a Cursor → Iterator for executing commands & retrieving results
  3. Execute SQL → Run Insert, Update, Delete, Select
  4. Transaction Management:
    • commit() → makes changes permanent
    • rollback() → reverts changes if error occurs
  5. Close Resources: Close cursor → then connection

Key Programming Methods and Examples

1. Connecting & Error Handling: use try-except block for safe connections.

Python
conn = psycopg2.connect(
    database="name", user="user", password="pw", host="host", port="port"
)

2. CRUD Operations:

  • Create Table: via cursor.execute() with multi-line SQL
  • Insert: Use placeholders %s to prevent SQL injection
  • Update/Delete: Similar to Insert; check cursor.rowcount for affected rows
  • Select/Fetch:
    • cursor.fetchone() → one row
    • cursor.fetchmany(size) → specified number of rows
    • cursor.fetchall() → all remaining rows

Web Frameworks and Flask

Frameworks:

  • Django, Pyramid → large/heavy
  • Flask, Bottle → micro-frameworks

Flask Specifics:

  • Micro-framework for WSGI
  • Routing: @app.route() binds URL to Python function
  • Rendering Templates: render_template() interprets HTML → displays nicely in browser

Integrated Application Example: Candidate Email Database

Frontend (index.html): Links: "Add Email", "View Email"

Adding Data:

  • HTML form collects data
  • Flask route (save_details) captures form values
  • Opens DB connection → executes INSERT → commits change

Viewing Data:

  • Flask route (view_all) executes SELECT
  • Uses cursor.fetchall() to retrieve rows
  • Results passed to render_template() → populates HTML table (view.html)
Final Quick Revision
  • Tech stack: Python + PostgreSQL (psycopg2)
  • Workflow: Connect → Cursor → Execute → Commit/Rollback → Close
  • CRUD operations with safe placeholders %s
  • Flask: lightweight framework for routing & templates
  • Integrated example: Candidate Email Database with add/view functionality

Lecture 5: Application Design and Development / 5

Rapid Application Development (RAD)

Overview:

  • RAD = Agile, fast, iterative development
  • Focuses on quick prototypes & customer feedback
  • Alternative to Waterfall model (linear, slower)

Key Characteristics:

  • Customer-in-the-Loop
  • Early prototypes ("sketchy versions") → feedback → improvement
  • Iteration & Integration → short cycles between versions
  • Integrate business, data, and process models from start

Speeding Up Development

TechniqueExample
Function LibrariesFlask (Python) → generates UI quickly
IDEsVisual Studio → drag & drop UI creation
Code GenerationAuto procedural code from declarative specs (SQL)

Four Phases of RAD

  1. Business Modelling → Identify goals & requirements
  2. Data Modelling → Define entities, attributes, constraints
  3. Process Modelling → Map workflows (e.g., e-commerce: search → cart → payment → tracking)
  4. Testing & Turnover → Prototype → feedback → finalize

RAD Frameworks & Platforms

PlatformKey Feature
Java Server FacesUI components + states + events + accessibility
Ruby on RailsAuto-generate CRUD interfaces from DB schema
Cloud PlatformsG Suite, Google App Engine, AWS, Azure, ASP.NET

Performance & Caching

Server-Side Caching:

  • Connection pooling (e.g., JDBC connections)
  • Cache DB query results
  • Cache full HTML pages

Client-Side Caching:

  • Web proxies store responses locally
  • Reduces requests to server
Challenge Avoid dirty data → must update caches when DB changes.

Security Measures

Threat/NeedCountermeasure
SQL InjectionValidate inputs, use prepared statements
PasswordsEncrypt; never store plaintext
Access ControlLimit DB access to specific server IPs
Authentication2FA → SMS, OTP, biometrics
AuthorizationTable/column-level vs row-level → app layer
Audit TrailsLog all actions for investigation & repair

Mobile Application Development

Overview:

  • Mobile apps follow three-tier architecture like web apps
  • Environment is resource-constrained: limited memory, CPU, battery, bandwidth

Unique Mobile Features:

  • Hardware sensors: Accelerometer → detect speed/motion; Gravity sensor → screen rotation
  • Gesture-based navigation

Types of Mobile Presence

TypeDescription
Mobile WebsitesHTML designed for touch + small screens
Mobile Apps (Native)Installed, may work offline using local cache/db
Hybrid AppsCombine native features + web view

Mobile Architecture

Split Data Layer:

  • Local database → fast access
  • Remote database → full data over network

Platform Specificity:

  • iOS → Objective-C / Swift
  • Android → Java, C, C++
  • Hybrid → Cross-platform options

Example: Mobile App Offline Cache (Conceptual):

Python
local_db = {}  # small local DB

def fetch_data(item_id):
    if item_id in local_db:
        return local_db[item_id]  # fast local access
    else:
        data = fetch_from_remote_server(item_id)
        local_db[item_id] = data  # cache for next time
        return data
Quick Summary
  • RAD → Agile, iterative, customer feedback, fast prototypes
  • Performance → Caching, connection pooling, prevent dirty data
  • Security → SQL injection, encrypted passwords, 2FA, audit logs
  • Mobile Apps → Resource-constrained, sensors, offline caching, platform-specific or hybrid
