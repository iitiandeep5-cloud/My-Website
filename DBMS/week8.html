Lecture 1: Algorithms and Data Structures / 1 — Algorithms & Complexity Analysis

DBMS Context

  • Logical Design → Defines what data looks like (tables, relationships, constraints).
  • Physical Design → Defines how data is stored (files, indexes, storage layout).
  • Goal → Optimize access time and storage usage.

Algorithm vs Program

Algorithm: step-by-step procedure to solve a problem; must be finite, well-defined, and always terminate.

Program: code written in a programming language; implements an algorithm; may run indefinitely (e.g., OS, DBMS).

Summary Algorithm = Idea. Program = Implementation.

Why Analyze Algorithms?

  • Limited resources → need efficiency
  • Predict performance before execution
  • Compare algorithms (e.g., QuickSort vs MergeSort)
  • Guarantee performance (e.g., trees, indexing)

What Do We Analyze?

  • Input Size (n): Number of elements / data size
  • Resources: Time (most important), Space (memory usage), Power (mobile devices), Bandwidth (distributed systems)

Methods of Analysis

  • Counting Model: Count key operations (comparisons, additions)
  • RAM Model: Assume each operation takes constant time
  • Asymptotic Analysis: Focus on growth as n increases
  • Recursive Analysis: Use recurrence relations, Master's Theorem

Big-O Complexity

ComplexityMeaningExample
O(1)ConstantArray access
O(log n)Very fastBinary search
O(n)LinearSimple loop
O(n log n)EfficientMerge sort

Rule: Ignore constants, keep dominant term only.

Optimization Examples

Inefficient:

C
for(i=0; i<strlen(s); i++)

Efficient:

C
len = strlen(s);
for(i=0; i<len; i++)

Reduces O(n²) → O(n)

Space Optimization

  • Recursive factorial → O(n) space
  • Iterative factorial → O(1) space
  • Avoid recursion when memory matters

Analysis Scenarios

  • Worst Case: Maximum time taken, guarantees performance
  • Average Case: Expected performance, depends on input distribution
Final Revision Design → Algorithm → Program → Analysis → Optimization

Lecture 2: Algorithms and Data Structures / 2 — Data Structures

What are Data Structures?

A data structure is a container plus operations. Used to organize data in memory (temporary). Unlike databases → no persistence (only during program execution).

Common Operations: Create, Insert, Delete, Search (Find), Close

Foundational Mechanisms

All data structures are based on two core storage ideas:

Indexed / Sequential Data stored in continuous memory. Access using: Address = Base + Index × Size. Fast random access.
Referential (Pointers) Elements stored anywhere in memory. Connected using addresses (links). Flexible but slower access.

Linear Data Structures

Elements arranged one after another. Each element points to the next.

Arrays (Sequential)

Key Points: Stored in contiguous memory. Access → O(1) (very fast). Fixed size.

Drawbacks: Insert/Delete → O(n) (shifting required). Possible wasted space.

Best for: Fast access; sorted data (binary search).

Linked Lists (Referential)

Key Points: Nodes = Data + Pointer. No need for continuous memory. Dynamic size.

Drawbacks: Access → O(n) (traversal needed).

Advantage: Insert/Delete → O(1) (just change pointers).

Best for: Frequent insertions/deletions.

Stacks & Queues (Concept-Based)

  • Stack (LIFO – Last In First Out): Operations: Push, Pop. Time: O(1)
  • Queue (FIFO – First In First Out): Operations: Enqueue, Dequeue. Time: O(1)

Searching Techniques

Linear Search: Check elements one by one. Works on Arrays and Linked Lists. Time: O(n).

Binary Search: Divide search space into half. Time: O(log n).

Requirements: Sorted data; Indexed structure (Array). Not suitable for Linked Lists.

Final Memory Trick — "A-L-S-Q Rule"
  • Array → Access fast
  • Linked List → Insert/Delete fast
  • Stack → LIFO
  • Queue → FIFO

Lecture 3: Algorithms and Data Structures / 3 — Data Structures

Overview of Data Structures

Definition: A data structure is a way to organize and store data in memory for efficient use.

Goals: Faster access; efficient modification.

Efficiency Measures: Time Complexity (most important); Space Complexity.

Basic Operations: Create, Insert, Delete, Find (Search), Access, Close

Linear vs Non-Linear Structures

Linear Structures (1D flow): elements arranged sequentially; Space Complexity → O(n).

  • Arrays → Fast access (O(1)), slow insert/delete (O(n))
  • Linked Lists → Fast insert/delete (O(1)), slow access/search (O(n))

Non-Linear Structures: data arranged in hierarchy or network; multiple paths possible.

  • Graph: collection of vertices (nodes) and edges (connections). Types: Directed/Undirected, Weighted/Unweighted, Cyclic/Acyclic
  • Tree (Special Graph): connected, no cycles; hierarchical structure
  • Hash Table: uses hash function to convert key → index; stored in array form; very fast access (average O(1))
  • Skip List: multi-level linked list; faster search than normal linked list; average time: O(log n)

Tree Terminology & Properties

Basic Terms:

  • Root → Top node (no parent)
  • Parent / Child → Hierarchical relation
  • Leaf Node → No children
  • Internal Node → Has children
  • Arity → Number of children

Structure Concepts:

  • Path → Sequence of nodes
  • Subtree → Tree inside a tree
  • Level → Distance from root
  • Height (h) → Longest path root → leaf
Important Facts Tree with n nodes → n−1 edges.
Maximum nodes at level l = 2ˡ (binary tree).
Height: Best case → O(log n); Worst case → O(n)

Binary Search Tree (BST)

Concept: Combines array's search efficiency with linked list's flexibility.

BST Rule For node X: Left subtree → values < X. Right subtree → values > X.

Operations: Search → Move left/right → O(h). Insert/Delete → Search + pointer change → O(h).

Efficiency: Balanced Tree → O(log n). Skewed Tree → O(n).

Traversals

  • Depth First Search (DFS): In-order, Pre-order, Post-order
  • Breadth First Search (BFS): Level-wise traversal

Performance Summary

Linked ListO(n)O(1)O(1)
BST (avg)O(log n)O(log n)O(log n)

Advanced Trees

  • Red-Black Tree
  • B-Tree

Both maintain: Height = O(log n), even in worst case.

Final Revision Tricks
  • "L vs NL Rule": Linear → Simple, sequential. Non-linear → Hierarchical, powerful.
  • BST Rule: Left < Root < Right

Lecture 4: Storage and File Structure / 1 — Physical Storage

Overview of Database Storage

Databases require persistent storage. Data must survive power failure and system crash.

Key Evaluation Factors:

  • Speed → Fast access to data
  • Cost → Low cost per GB
  • Reliability → Data safety & recovery

Storage Hierarchy

Storage is organized from fastest → slowest and costliest → cheapest.

Primary Storage (Volatile) Data lost when power is OFF.
Types: Cache → Fastest, most expensive; Main Memory (RAM) → Very fast (nanoseconds), limited size.
Secondary Storage (Persistent) Stores actual database data. Non-volatile.
Types: Magnetic Disks (HDD) → Most common; Flash Memory (SSD) → Faster than HDD, requires erase before rewrite.
Tertiary Storage (Archival) Used for backup & history. Cheap but slow.
Types: Optical Disks (CD/DVD) → Write once; Magnetic Tapes → Sequential access.

Magnetic Disk Architecture

Components: Platters (spinning disks); Read/Write Head; Arm Assembly.

Disk Geometry:

  • Tracks → Circular paths
  • Sectors → Smallest unit (e.g., 512 bytes)
  • Cylinders → Same track across platters
  • Blocks/Clusters → Group of sectors

Disk Controller: Controls head movement; ensures data correctness (checksums); detects bad sectors.

Performance Metrics

  • Access Time: Seek Time → Move head to track; Rotational Latency → Wait for sector
  • Data Transfer Rate: Speed of reading/writing data (~25–100 MB/s)
  • Reliability: MTTF (Mean Time To Failure); average lifespan ≈ 3–5 years

Modern & Future Technologies

  • Cloud Storage: Platforms: Google Drive, AWS. Backup & recovery handled. Scalable & cost-effective.
  • SSD (Solid State Drive): No moving parts; faster than HDD; more expensive.
  • DNA Storage (Future): Extremely high capacity; very slow & costly (currently).
  • Quantum Memory (Future): Uses qubits instead of bits; potential for massive efficiency.

Revision Trick — "P-S-T Rule"
  • Primary → Fast but temporary
  • Secondary → Main database storage
  • Tertiary → Backup/archive

Lecture 5: Storage and File Structure / 2 — File Structure

Basic Mental Model

Hierarchy: Database → Files → Records → Fields

  • File: Collection of records
  • Record: Collection of fields
  • Field: Smallest unit (attribute)

Storage Units: Data stored in blocks (pages). Block = group of disk sectors. Block is the basic unit for storage allocation and data transfer.

Record Management

Fixed-Length Records: All records have same size. Easy access using formula: Address + (i × size)

Deletion Problems & Solutions:

  • Compaction → Shift records to fill gap (expensive)
  • Last Record Movement → Replace deleted record with last record (faster)
  • Free List (Best) → Store deleted record addresses, link them like a chain

Variable-Length Records: Used when there are multiple record types, VARCHAR fields, or repeating attributes.

Structure: Fixed part → stores length, offset (pointer). Variable part → actual data.

Null Values: Stored using Null Bitmap. Each bit represents presence/absence.

Slotted Page Structure

Key Idea Page contains: Header, Slot directory, Records.

Advantages: Records can move inside page; external references remain valid; efficient space usage.

Physical File Organization

  • Heap File: Records stored anywhere; fast insert; slow search.
  • Sequential File: Records stored in sorted order; good for sequential access; needs reorganization.
  • Multi-table Clustering: Related records stored together. Example: Department + Instructor.

Pros: Faster join operations. Cons: Inefficient for single-table queries.

Data Dictionary (System Catalog)

Stores metadata (data about data).

Contains: Table names; attributes & types; index information; constraints; user permissions.

Performance Tip Often kept in main memory because it is accessed frequently.

Buffer Management

Buffer: Area in RAM storing disk blocks. Reduces slow disk access.

Buffer Manager: Handles block requests — if block exists → use it; if not → fetch from disk.

Replacement Policies:

  • LRU (Least Recently Used) → Remove least used block
  • MRU (Most Recently Used) → Remove recent block (useful in joins)

Special Concepts:

  • Pinned Block → Cannot be removed (in use)
  • Toss-Immediate → Free block immediately after use
Final Revision Trick — "F-R-B Rule"
  • Files → Organized data
  • Records → Data units
  • Buffer → Speeds up access
Ultra-Short Summary
  • Data stored as: DB → File → Record → Field
  • Blocks = basic storage unit
  • Fixed records → simple, fast access
  • Variable records → flexible
  • Slotted pages → flexible storage inside block
  • Heap vs Sequential → trade-off
  • Buffer → improves performance
