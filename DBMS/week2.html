Lecture 1: Introduction to Relational Model / 1

Basic Concepts

Relation (Table): A relation is a table consisting of rows and columns.

Attributes (Columns)

  • Represent properties (e.g., Name, Age)
  • Order does not matter, but names must be unique
  • Must be atomic → no multi-valued fields (e.g., avoid combining first & last name in one column)

Tuples (Rows)

  • Each row represents a single record

Domain

  • Set of valid values for an attribute
  • Example: Age → only numbers, Date → valid date format

Null Values

  • Represent unknown or missing data
  • Some attributes allow null (optional), others do not (mandatory like Roll No)

Schema vs Instance

Schema: Structure/design of the table.

Notation: R(A₁, A₂, …, Aₙ)

Example: Student(Name, RollNo, Age)

Instance: Actual data present at a given time.

Mathematical View: Relation = subset of Cartesian Product → D₁ × D₂ × ... × Dₙ

Set Properties

  • No duplicate rows
  • Order of rows does not matter

Keys

  • Superkey: Any set of attributes that uniquely identifies a row
  • Candidate Key: Minimal superkey (no extra attributes). Can have multiple candidate keys
  • Primary Key: Chosen candidate key. Must be unique and non-null
  • Alternate Key: Candidate keys not selected as primary key
  • Surrogate Key: Artificial key (e.g., ID, Order Number)
  • Foreign Key: Attribute in one table referring to another table's primary key. Used to create relationships

Choosing a Good Primary Key

  • Uniqueness: Avoid attributes like Name (not unique)
  • Non-null: Primary key cannot be NULL
  • Meaningful (Optional): Keys like Roll No may encode info (year, dept)

Relational Query Languages

  • Procedural Language: Specifies how to get data. Examples: C, Java, Python
  • Declarative Language: Specifies what data is needed. Example: SQL

Models in Relational Systems

  • Relational Algebra
  • Tuple Calculus
  • Domain Calculus

Note: These models are not Turing complete.

Quick Summary

  • Relation = Table
  • Attribute = Column (atomic)
  • Tuple = Row
  • Domain = Valid values
  • Schema = Structure, Instance = Data
  • No duplicate rows (set property)
  • Keys → Superkey ⊇ Candidate Key ⊇ Primary Key
  • Foreign key → connects tables
  • SQL = Declarative language

Lecture 2: Introduction to Relational Model / 2

Fundamental Concepts

Relation as a Set

  • A relation is treated like a mathematical set
  • Order of rows does not matter
  • No duplicate tuples: every row must be unique, duplicates are automatically removed

Input & Output Rule

  • Every operation takes relation(s) as input
  • Always produces a relation (table) as output
  • Enables chaining of operations

Relational Operators

A. Unary Operators (Single Table)

Selection (σ):

  • Filters rows based on condition
  • Example: σ(age > 18)
  • Equivalent to WHERE in SQL

Projection (π):

  • Selects specific columns
  • Removes unwanted columns
  • Automatically removes duplicate rows
  • Equivalent to SELECT columns in SQL

B. Binary Operators (Two Tables)

Union (∪):

  • Combines rows of two relations
  • Conditions: Same attributes (same schema)
  • Removes duplicates

Set Difference (−):

  • Returns rows in r but not in s

Intersection (∩):

  • Common rows in both tables
  • Not a basic operator → can be derived: r∩s = r−(r−s)

Cartesian Product (×):

  • Combines all rows of r with all rows of s
  • Produces all possible pairs
  • Can create very large tables

Attribute Naming Rule

  • If same column names exist → use prefix
  • Example: r.A, s.A

Special Operations

Renaming (ρ):

  • Changes table or column names
  • Useful in self-join (r × r)
  • Avoids confusion

Natural Join (⋈):

  • Combines tables using common attributes
  • Keeps only matching rows
  • Removes duplicate columns
  • More efficient than Cartesian product

Aggregate Operations

Purpose: Perform calculations on data.

Examples

  • SUM
  • AVG
  • MAX
  • MIN
  • COUNT

Output: Returns a single value (not a table).

Usage

  • Can be applied after filtering
  • Example: Average marks of students with marks > 50

Key Characteristics

  • Input/Output: Tables → Operation → Table
  • Chaining: Output of one operation can be used as input for another
  • Not Turing Complete: Cannot solve all computational problems alone
  • Needs support of programming languages (e.g., SQL + Python)

Quick Revision

  • Relation = Set (no order, no duplicates)
  • σ → Rows filter
  • π → Columns select
  • ∪ → Combine tables
  • − → Difference
  • × → All combinations
  • ⋈ → Smart join
  • ρ → Rename
  • Aggregates → Single value output
  • Output is always a table (except aggregates)

Lecture 3: Introduction to SQL / 1

Introduction & History

Origin: Developed by IBM in the 1970s–80s as SEQUEL for the System R project.

Standardization

  • SQL-86: First ANSI standard
  • SQL-92: Most important base standard (widely used)
  • SQL:1999: Added recursive queries, triggers, and procedural features
  • Later updates: XML support (2003/2006), latest → SQL:2019

Important Note: SQL is the industry standard, but syntax may vary across databases (MySQL, Oracle, etc.).

Alternatives

  • QUEL (rarely used)
  • SPARQL → used for graph/RDF databases

Data Definition Language (DDL)

Purpose: Used to define and modify database structure (schema).

Common Data Types

  • char(n) → Fixed-length string
  • varchar(n) → Variable-length string
  • int, smallint → Integers
  • numeric(p, d) → Exact decimal values
  • float → Approximate numbers

Table Creation

  • CREATE TABLE → Creates a new table
  • Defines: table name, columns (attributes), data types

Integrity Constraints

  • NOT NULL → Value must exist
  • PRIMARY KEY → Unique + non-null
  • FOREIGN KEY → Links tables (referential integrity)

Schema Modification

  • DROP TABLE → Deletes table completely
  • ALTER TABLE → Add/remove columns
  • DELETE FROM table → Deletes all rows (structure remains)

Data Manipulation Language (DML)

Purpose: Used to query and manipulate data.

SQL Nature: Declarative language → You specify what you want, not how to get it.

Basic Query Structure

SELECT column_name
FROM table_name
WHERE condition;

SELECT Clause (Projection)

  • Selects columns
  • Allows duplicates by default
  • Options:
    • DISTINCT → remove duplicates
    • ALL → keep duplicates
  • Special features:
    • * → all columns
    • Calculations → salary / 12
    • Renaming → AS

FROM Clause (Tables)

  • Specifies tables involved
  • Multiple tables → Cartesian Product (default)

WHERE Clause (Selection)

  • Filters rows using conditions
  • Uses comparisons (=, <, >) and logical operators (AND, OR, NOT)
  • Used for joining tables (e.g., matching IDs)

Key Characteristics

  • Case-Insensitive: SELECT = select = SeLeCt
  • User-Friendly: Easy and intuitive syntax
  • Default Behavior: New columns get NULL values for existing rows
  • Embedding Support:
    • SQL inside Java → SQLJ
    • Java inside SQL → SQL/JRT

Quick Revision

  • SQL = Declarative language
  • DDL → Structure (CREATE, ALTER, DROP)
  • DML → Data (SELECT, WHERE)
  • SELECT → columns
  • FROM → tables
  • WHERE → conditions
  • Default allows duplicates → use DISTINCT
  • Keys → Primary & Foreign
  • Case-insensitive

Lecture 4: Introduction to SQL / 2

Cartesian Product & Joins

Cartesian Product (×)

  • Combines every row of one table with every row of another
  • Occurs when multiple tables are listed in FROM without conditions
  • Produces large, often meaningless data

Qualified Names

  • Used when columns have the same names
  • Format: table.column
  • Example: instructor.ID, teaches.ID

Join using WHERE

SELECT *
FROM instructor, teaches
WHERE instructor.ID = teaches.ID;

Natural Join (⋈)

  • Automatically joins tables using common attributes
  • Removes duplicate columns
  • More efficient and cleaner than manual joins

Renaming & Self-Joins

AS Clause (Renaming)

  • Used to rename tables or columns
  • Example: instructor AS T

Self-Join

Joining a table with itself using aliases.

FROM instructor T, instructor S
  • Uses: compare rows within the same table, find hierarchical relations (e.g., manager → employee)

String Operations

LIKE Operator: Used for pattern matching.

Wildcards

  • % → Any sequence of characters
    • Example: %dar% → matches Darwin, Sardar
  • _ → Single character
    • Example: _ar → matches car, bar

Case Sensitivity: Strings inside quotes are case-sensitive.

Other Functions

  • Concatenation
  • UPPER(), LOWER()

Sorting & Limiting Results

ORDER BY

  • Sorts output
  • Default → Ascending (ASC)
  • Use DESC for descending: ORDER BY salary DESC;

Limiting Rows (Database-Specific Syntax)

DatabaseSyntax
MySQLLIMIT n
SQL ServerTOP n
Oracle/StandardFETCH FIRST n ROWS ONLY

Advanced WHERE Conditions

BETWEEN ... AND ...

  • Range condition
  • Example: salary BETWEEN 90000 AND 100000

Tuple Comparison

  • Compare multiple attributes together

IN Operator

  • Check membership in a set
  • Example: dept_name IN ('CS', 'Biology')

Duplicate Handling (Multisets)

  • SQL uses Multisets (not pure sets): Duplicates are allowed
  • Default Behavior: Operations keep duplicates
  • Remove duplicates: Use DISTINCT

Quick Revision

  • Cartesian Product → all combinations
  • WHERE → converts product into join
  • Natural Join → auto join on common columns
  • AS → rename tables
  • Self-join → table with itself
  • LIKE → pattern matching (%, _)
  • ORDER BY → sorting
  • LIMIT / TOP → restrict rows
  • BETWEEN, IN → conditions
  • SQL allows duplicates → use DISTINCT

Lecture 5: Introduction to SQL / 3

Set Operations

SQL can treat tables like sets (no duplicates).

Requirements

  • Both queries must have the same number of columns
  • Columns must have the same data types

Main Operations

  • UNION → Combines results (like OR), removes duplicates
  • INTERSECT → Common records (like AND)
  • EXCEPT → Records in first but not in second

Multiset Versions (Allow Duplicates)

  • UNION ALL → m + n occurrences
  • INTERSECT ALL → min(m, n)
  • EXCEPT ALL → m − n (or 0)

NULL Values

Meaning

  • Represents unknown or missing value

Usage

  • Missing data
  • Newly added columns

Important Points

  • NULL ≠ 0
    • 0 → known value
    • NULL → unknown

Operations with NULL

  • Arithmetic → Result = NULL
  • Comparison → Cannot use =

Correct Usage

  • IS NULL
  • IS NOT NULL

Three-Valued Logic

SQL uses 3 logical values:

  • TRUE
  • FALSE
  • UNKNOWN

Logic Rules

  • OR:
    • TRUE OR UNKNOWN → TRUE
    • FALSE OR UNKNOWN → UNKNOWN
  • AND:
    • FALSE AND UNKNOWN → FALSE
    • TRUE AND UNKNOWN → UNKNOWN
  • NOT:
    • NOT UNKNOWN → UNKNOWN

WHERE Clause Rule: UNKNOWN is treated as FALSE → row is excluded.

Aggregate Functions

Operate on a column → return single value.

Main Functions

  • AVG() → Average
  • MIN() / MAX() → Smallest / Largest
  • SUM() → Total
  • COUNT() → Number of rows

COUNT Variants

  • COUNT(*) → All rows
  • COUNT(column) → Non-null values
  • COUNT(DISTINCT column) → Unique values

NULL Handling

  • Ignored in AVG, SUM, etc.
  • Special case: Only NULL values →
    • COUNT → 0
    • Others → NULL

GROUP BY & HAVING

GROUP BY

  • Groups rows based on column values
  • Example: Salary per department

Rule: SELECT can only contain grouped columns or aggregate functions.

HAVING

Filters groups (after grouping).

Difference

ClauseWorks On
WHEREIndividual rows
HAVINGGroups (after grouping)

Quick Revision

  • UNION / INTERSECT / EXCEPT → set operations
  • ALL → keeps duplicates
  • NULL = unknown (not 0)
  • Use IS NULL (not =)
  • SQL uses 3 logic → TRUE, FALSE, UNKNOWN
  • UNKNOWN → treated as FALSE in WHERE
  • Aggregates → AVG, SUM, COUNT
  • NULL ignored in aggregates
  • GROUP BY → grouping
  • HAVING → filter groups
